## 2 第一优先级：直接支撑毕业设计主体

### 2.1 Spark SQL: Relational Data Processing in Spark

- 文件：[02_Armbrust_2015_Spark_SQL.pdf](./02_Armbrust_2015_Spark_SQL.pdf)
- 作者：Michael Armbrust 等
- 出处：ACM SIGMOD 2015
- 主要内容：Spark SQL、DataFrame、关系型处理与 Catalyst 优化器。
- 对项目的作用：支撑论文第二章 Spark SQL 原理，以及第五章 Spark 数据处理、逻辑计划和优化策略。
- 建议重点阅读：系统架构、Catalyst、DataFrame 与 SQL 的关系、性能实验。
- 可以形成的论文内容：解释为什么本项目使用 Spark SQL 执行 ETL 和指标聚合，以及分区裁剪、广播连接等优化为什么有效。

### 2.2 Spider: A Large-Scale Human-Labeled Dataset for Complex and Cross-Domain Semantic Parsing and Text-to-SQL Task

- 文件：[03_Yu_2018_Spider_Text_to_SQL.pdf](./03_Yu_2018_Spider_Text_to_SQL.pdf)
- 作者：Tao Yu 等
- 出处：EMNLP 2018
- 主要内容：跨数据库 Text-to-SQL 数据集、复杂 SQL 分类和评估方式。
- 对项目的作用：支撑 Text-to-SQL 问题集设计、难度分层和执行正确率评价。
- 建议重点阅读：数据集拆分、跨领域泛化、SQL 难度划分、Exact Match 指标。
- 使用边界：项目不需要复现 Spider 模型，只借鉴问题分类和评估方法，并建立自己的电商指标测试集。

### 2.3 PICARD: Parsing Incrementally for Constrained Auto-Regressive Decoding from Language Models

- 文件：[04_Scholak_2021_PICARD_Constrained_SQL.pdf](./04_Scholak_2021_PICARD_Constrained_SQL.pdf)
- 作者：Torsten Scholak、Nathan Schucher、Dzmitry Bahdanau
- 出处：EMNLP 2021
- 主要内容：在生成过程中使用增量解析约束无效 SQL。
- 对项目的作用：支撑“模型输出不能直接执行”“语法约束能够提高可执行性”的研究依据。
- 与本项目的区别：本项目不实现 PICARD 的解码器，而是在生成后使用 JSqlParser、白名单、EXPLAIN 和只读账号进行多级校验。
- 可以形成的对比：无校验、字符串校验、AST 校验、AST 加执行反馈四组方案。

### 2.4 DIN-SQL: Decomposed In-Context Learning of Text-to-SQL with Self-Correction

- 文件：[06_Pourreza_2023_DIN_SQL_Self_Correction.pdf](./06_Pourreza_2023_DIN_SQL_Self_Correction.pdf)
- 作者：Mohammadreza Pourreza、Davood Rafiei
- 出处：NeurIPS 2023
- 主要内容：将 Text-to-SQL 分解为 Schema Linking、查询分类、SQL 生成和自纠错等步骤。
- 对项目的作用：直接支撑“意图识别—Schema 选择—SQL 生成—错误反馈—一次修复”的流程设计。
- 建议重点阅读：任务分解、Prompt 组织、自纠错流程和消融实验。
- 使用边界：只借鉴分解思想，不照搬复杂多代理结构；首版保持 Java 单服务编排。

### 2.5 Can LLM Already Serve as A Database Interface? BIRD Benchmark

- 文件：[07_Li_2023_BIRD_Large_Scale_Text_to_SQL.pdf](./07_Li_2023_BIRD_Large_Scale_Text_to_SQL.pdf)
- 作者：Jinyang Li 等
- 出处：NeurIPS 2023 Datasets and Benchmarks
- 主要内容：面向大规模真实数据库内容的 Text-to-SQL 基准，强调数据库值、外部知识和执行效率。
- 对项目的作用：说明只提供表结构不足以支持真实业务查询，指标口径、字段取值和业务知识同样重要。
- 建议重点阅读：数据库内容对查询的影响、执行准确率、有效效率评分、错误类别。
- 可以形成的实验：仅 Schema、Schema 加指标字典、再加入少样本和自动修复的消融实验。

### 2.6 Automating Large-Scale Data Quality Verification

- 文件：[08_Schelter_2018_Large_Scale_Data_Quality_Verification.pdf](./08_Schelter_2018_Large_Scale_Data_Quality_Verification.pdf)
- 作者：Sebastian Schelter 等
- 出处：PVLDB 2018
- 主要内容：在 Spark 上声明式执行大规模数据质量约束，可视为面向数据的自动化测试。
- 对项目的作用：支撑完整性、唯一性、合法性、金额对账、历史波动和增量质量检查设计。
- 建议重点阅读：约束模型、Spark 聚合执行、增量计算、历史质量异常检测。
- 可以形成的实现：质量规则表、规则执行器、质量结果表、失败阻止 ADS 快照发布。

### 2.7 An Exploration of Clustering Algorithms for Customer Segmentation in the UK Retail Market

- 文件：[13_John_2023_RFM_Clustering_Comparison.pdf](./13_John_2023_RFM_Clustering_Comparison.pdf)
- 作者：Jeen Mary John、Olamilekan Shobayo、Bayode Ogunleye
- 出处：Analytics, 2023；公开稿收录于 arXiv 2024
- 主要内容：使用 541,909 条在线零售记录构建 RFM，并比较 K-Means、GMM、DBSCAN、层次聚类和 BIRCH。
- 对项目的作用：支撑 RFM 特征、标准化、聚类算法比较和轮廓系数评价。
- 首版建议：先实现易解释的 RFM 分位数分层；K-Means 或其他聚类作为增强实验，不作为系统主链路依赖。

## 6 可以直接借鉴的实验指标

- Spark：运行时间、吞吐量、Shuffle 数据量、不同分区/广播策略的均值和标准差；
- 数据质量：规则通过率、异常检出率、误报率、检查耗时、阻止错误快照发布次数；
- Text-to-SQL：Valid SQL、Execution Accuracy、结果集合一致率、指标口径正确率、安全拦截率、平均延迟；
- RFM/聚类：轮廓系数、Davies-Bouldin 指数、不同随机种子的稳定性和业务可解释性；
- 数据生成：字段分布距离、场景方向命中率、订单状态合法率、金额一致率、随机种子复现率；
- 异常分析：Precision、Recall、F1，以及不同阈值下的误报与漏报。

## 7 引用与学术规范提示

- 不要直接复制论文架构图、表格和大段原文；需要自己重画、概括并标注来源。
- 论文中的实验数字只能作为相关工作结果，不能当作本项目实测结果。
- arXiv 或作者公开稿可以用于阅读，但参考文献优先填写正式发表的会议或期刊信息。
- 项目使用规则式 RFM、生成后 SQL 校验和场景化生成器时，应明确与相关论文方法的区别。
- 最终写论文时还需根据学校格式统一为 GB/T 7714，并核对作者、年份、卷期、页码和 DOI。

同目录的 `毕业设计核心论文参考文献.bib` 可以导入 Zotero、JabRef 或 LaTeX；正式提交前仍需逐条核对学校要求。
