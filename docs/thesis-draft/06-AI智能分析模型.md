# 第六章 智能分析模型设计实现（初稿）

> 对应实现：`mall-simulator/ai/`（语义层/校验器/执行器/解释器）、`ai_query_history` 等审计表。
> 关键实验证据：`experiments/ai-eval-*.json`（100 题安全/可用性评测）。

## 6.1 设计原则

智能分析模型遵循六条基线（§8.1）：

1. 大模型只查询 ADS 白名单（物化指标宽表），不直接扫描 ODS/DWD 明细；
2. 指标含义来自语义层（表/字段/别名/少样本），不由模型临时猜测；
3. SQL 必须先解析和校验（四层），通过后才执行；
4. 查询结果是回答的唯一数据证据，结论不得引用结果之外的数值；
5. 推测与事实分开表达（possibleCauses 与 facts 分栏）；
6. 失败过程可重试、可记录、可人工检查（至多一次修复 + 全链路审计）。

## 6.2 业务语义层

语义层是可查询 Schema 的唯一事实来源：

- 每张 ADS 表声明字段级业务含义、单位与口径（如 sale_amount：仅统计有效支付订单、
  单位元、可求和、不可用平均替代客单价）；
- 中文别名表（销售额/GMV/收入→sale_amount；净销售额→net_sale_amount）用于问题匹配；
- 每表提供 2–3 条正确问答少样本（问句→SQL），引导模型按口径书写；
- Schema 选择采用轻量关键词映射（1–3 张表），不依赖向量库（记为可选实验）。

## 6.3 受控 Text-to-SQL 流程

问题经"规范化→主题与指标识别→Schema 与少样本选择→LLM 生成结构化 JSON
（intent/metrics/dimensions/time_range/sql/assumptions）→四层校验→失败反馈
至多一次修复→EXPLAIN 级保护→只读执行"后返回真实结果。模型输出限定 JSON；
问题未给时间范围时默认近 30 天并写入 assumptions，避免无界查询。

Prompt 内嵌约束：只输出一个只读 SELECT；只使用给定表字段；必须包含时间条件；
明细自动限行；不确定返回 clarification_needed 而非编造。SQL 生成温度 0，
解释温度 0.2（§8.10）。

## 6.4 四层 SQL 安全校验

| 层 | 手段 | 说明 |
|---|---|---|
| 一 | 字符串预检 | 多语句、注释逃逸、INSERT/UPDATE/DELETE/DROP 等 DML/DDL、UNION 拼接、系统库关键词 |
| 二 | JSqlParser 语法树 | 根必须为只读 Select/With；函数白名单（聚合/日期/数学子集）；禁止文件/网络管理函数 |
| 三 | 表白名单与字段 | 表 ∈ ADS 物化白名单；SELECT 字段必须存在于语义层；最多 3 表关联 |
| 四 | 资源与时间 | 无 LIMIT 自动补 500、上限 1000 强制重写；WHERE 必须引用 dt（时间条件）；执行 30 秒超时、只读连接 |

即使应用层校验失效，MySQL 侧只读账号构成最终防线（纵深防御）。

## 6.5 一次受控修复

当 SQL 在校验阶段失败时，把"错误类型（脱敏）+ 原问题 + 相关 Schema"回送模型，
允许修复一次；修复结果必须重新经历全部校验。超过次数或修复失败返回明确错误，
不循环调用。评测中 58 次修复均成功转化为合法 SQL（关联/窗口类查询的合法化）。

## 6.6 证据约束解释（§8.8）

执行后构造证据包：{快照 ID、原问题、SQL、表、返回行数、耗时、时间范围、口径版本}。
解释请求只携带"结果摘要（≤200 行）+ 证据元信息"，并要求输出结构化 JSON：

- summary：结论（只陈述结果支持的）；
- facts[ ]：数据事实，每条关联结果字段/行（evidenceIds）；
- possibleCauses[ ]：推测，含置信度（LOW/MEDIUM/HIGH）；
- suggestions[ ]：建议，含目标指标码（targetMetricCode）——可一键创建决策草稿；
- limitations[ ] / followUpQuestions[ ]。

推测与事实分离 + evidenceIds 校验即"证据约束"。模型不可用时自动降级为规则化摘要
（页面标注"规则回退模式"），固定看板与数据处理不受影响。

## 6.7 审计

每次问答落 ai_query_history（问题、SQL、表、状态、行数、耗时、反馈），
每次模型调用落 ai_call_log（用例、供应商、模型、令牌、耗时、状态）；
流水线/快照/决策均带 trace 关联，运行中心可从一个异常指标追溯到输入批次与模型调用。
敏感信息（密钥）仅存在于环境变量，错误信息不回显连接细节。

## 6.8 与决策闭环的联动

解释结果中的建议（带 targetMetricCode 与证据快照）经用户确认后创建决策草稿
（AI 只能创建 DRAFT）；人工审核时从当前活跃快照锁定目标指标基线；执行完成后
按目标方向计算改善率并评价（EFFECTIVE/PARTIAL/INEFFECTIVE/INSUFFICIENT_DATA），
评价记录显式声明"前后对比，非因果推断"。由此，智能分析从"问答"延伸到"行动与复盘"，
并以审计数据支撑论文的量化讨论。
