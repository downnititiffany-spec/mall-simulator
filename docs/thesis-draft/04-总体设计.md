## 4.1 总体架构

系统按"采集→存储→计算→服务→应用→智能"六层组织，全部应用为单体部署、独立进程与数据库：

| 层 | 组件 | 数据/接口 |
|---|---|---|
| 业务与采集 | mall-simulator（商城/生成器/Outbox/爬虫式断点采集） | JSON 事件 → Landing |
| 存储与计算 | HDFS/Hive 四层数仓 + Spark 作业链（Scala，11 个作业） | Parquet、dt 分区（压缩编码未在代码中固定，全仓无 Snappy 配置） |
| 指标服务 | MySQL 指标库（快照版本 + 唯一活跃 + 物化 ADS 宽表） | /api/v1/metrics |
| 业务服务 | Spring Boot 模块化单体（流水线/质量/审计/决策） | /api/v1/* |
| 应用 | Vue 3 + ECharts 看板（9 个业务页：大盘/漏斗/商品/销售/RFM/流水线/运维/决策/AI） | /api/v1 代理（dev 代理指向 8091） |
| 智能 | AI 语义层 + 受控 Text-to-SQL + 证据解释 + 规则降级 | LLM API（可替换） |

依赖规则：mall-simulator 不依赖后端；后端不依赖 AI 可用性（降级可运行）；
大模型不接触业务库（只读 + ADS 物化白名单）。

## 4.2 运行环境与配置切换

| 模式 | 数据落地 | 提交 | 可验证项 |
|---|---|---|---|
| LOCAL | 本地 Landing + 内嵌 Derby-Hive + MySQL | spark-submit local | 全链路（本文实测；当前唯一已激活环境） |
| SINGLE_NODE | 单机 HDFS/Hive 服务 | spark-submit client | 集群语义（待环境） |
| REMOTE_CLUSTER | node01-03 | SSH + spark-submit | 分档性能（待环境） |

切换隔离点：RuntimeProfile 配置（数据源/提交器/元数据地址），业务代码与作业零改动；
作业统一入口契约保证提交端可解析结果（JobResult JSON）。

## 4.3 关键设计决策记录（ADR 摘要）

| 决策 | 理由 | 验证 |
|---|---|---|
| 业务与 Outbox 同库同事务 | 保障"业务提交必有事件"，避免双写不一致 | OutboxTransactionTest 回滚测试 |
| event_id 唯一键 + DWD ROW_NUMBER 双去重 | 容忍 at-least-once 采集语义 | 黄金夹具单测 + 真库黄金断言 / 采集对账 |
| 快照"唯一 ACTIVE + 失败保旧" | 指标原子切换（归档旧指针在成功切换的同一事务内完成）；发布失败时旧 ACTIVE 指针保持不变 | 真库 IT（`MetricPublisherMySqlIT`）；真链发布失败负路径待补测 |
| ADS 物化宽表为 AI 唯一查询面 | 架构级阻断明细越权，且查询快（P95 24ms） | SqlSafetyValidator + perf-web-tier1.json |
| 指标只随快照变化 → 30s 快照级 TTL 缓存 | 降低重复解析聚合开销（语义正确） | perf-web-tier1.json（仅优化后 21~29ms；**优化前基线无留档，待补测**） |
| AI 只建 DRAFT + 人工批准锁基线 | 决策门禁与效果可评价 | DecisionServiceTest |
| LLM 无 key 自动降级规则模板 | AI 不阻塞主链路（§3.5.5） | 降级模式实测（`providerUsed=template`） |
| LOCAL 用等价实现替代 Flume/HDFS | 同一逻辑链路本机可复现 | 文件级断点采集实测（35 文件 / 402,859,259 字节 → 接受 866,680 行、隔离 0 行）+ 链实测 |

## 4.4 全链路数据流

```text
商城操作/生成器 → 业务事务+Outbox → 滚动 JSON（landing/events）
  → 断点采集（校验/隔离）→ ODS → DWD（去重清洗） → DWS（主题聚合） → ADS（指标）
  → 质量门 → 快照发布（唯一 ACTIVE）→ 物化 ADS 宽表
  → 固定看板 / AI（语义层→SQL→校验→执行→证据解释）→ 决策（草稿→审核→评价）
可观测：pipeline_run/stage、data_quality_result、ai_query_history（**含被拒绝的问句**）、
ai_call_log（仅真实模型调用时写入，当前未配置模型 Key 故为空表）、
decision_task/evaluation 全部落库并带 trace。
```

## 4.5 模块依赖与解耦

后端由 6 个 Maven 模块组成：`platform-common`（公共契约与工具）、`connection-ingestion`
（连接/采集）、`warehouse-pipeline`（流水线/质量/发布）、`metric-analysis`（指标与分析）、
`ai-decision`（受控 Text-to-SQL 与决策）、`platform-app`（唯一可运行模块，Spring Boot 打包）；
同进程内按边界分包、通过接口注入，禁止跨层直连表。模拟商城与生成器**不属于**本工程，
位于独立产品 `mall-simulator`（两者之间无 Maven 依赖）。测试按模块建立集成底座，
各模块可分别以 `mvn test` 执行（**测试总数以 R9 全量测试日志为准**，本稿不写具体数字）。
