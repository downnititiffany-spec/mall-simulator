# 第一章 绪论（初稿）

## 1.1 研究背景与意义

电商平台每日产生浏览、点击、收藏、加购、下单、支付、退款等海量用户行为日志。
随着数据规模到达百万级以上，传统关系型数据库在分析时效与口径统一上出现明显短板；
同时，业务运营人员大多不具备 Hive SQL 编写能力，数据分析门槛高、口径易漂移。
近年来大语言模型在 Text-to-SQL 任务上展现出潜力，但直接以模型生成 SQL 接入生产存在
三个核心风险：一是字段幻觉（将不存在或口径错误的字段带入 SQL）；二是口径错误
（同一指标在不同语义下被混用，如"销售额"与"净销售额"）；三是安全越权
（未经约束的 SELECT 可访问底层明细，甚至被注入改写语句）。

本课题的目标是设计并实现一套"基于 Spark 大数据平台和智能分析模型的电商用户行为分析系统"，
以数据工程为可信基础、业务应用为主要入口、AI 为横向增强能力：由 Spark/Hive 承担全部可信计算，
由受控 Text-to-SQL 与证据约束解释承担智能问答，并在人工审核下形成可追踪的决策闭环，
最终为普通电商运营人员提供"能看、能问、能做、能复盘"的自助分析体验。

## 1.2 国内外研究现状

（内容由作者补充引文后定稿。此处给出写作要点与可查证据，防止空谈：）

1. 数仓建模与电商分析：经典维度建模在企业数仓设计中成熟应用；开源生态 Hadoop/Hive/Spark
   提供海量数据离线加工能力，分层数仓（ODS/DWD/DWS/ADS）为分析口径统一提供了工程范式。
2. Text-to-SQL：学术界以 Spider、WikiSQL 等基准推动模型能力评测；工程界倾向"受约束生成+
   解析校验"的防御式架构，本文采用的"语义层裁剪 + 结构化输出 + 语法树校验 + 至多一次修复"
   即属于该路线的可落地实现，并以 ADS 白名单从架构上杜绝明细越权。
3. 可信 AI 分析：大模型结论的"证据约束"（引用结果中的字段与数值）是降低幻觉风险的关键；
   本文以执行证据（SQL、行数、耗时、口径、快照）与结论结构化输出绑定实现该约束，
   并以规则回退保证模型不可用不阻塞主线。

## 1.3 主要研究内容

本文围绕一条"业务发生→可靠采集→分层加工→质量校验→指标发布→固定看板→
智能问答→证据解释→人工决策→效果复盘"的完整链路开展设计与实现，主要研究内容为：

1. 面向电商场景的可复现数据工程：Java 模拟商城与场景化数据生成器、事务 Outbox 与
   断点采集、四层 Hive 数仓与 Scala Spark 作业链、快照版本化发布机制；
2. 面向数仓语义的智能分析模型：业务语义层、受控 Text-to-SQL 流程、四层 SQL 安全校验、
   一次受控修复、证据约束结果解释与结构化输出；
3. 决策闭环与审计：AI 建议→人工审核→锁定基线→效果评价的 12 态决策生命周期，
   以及查询历史/模型调用/流水线全链路审计；
4. 多层次实验验证：黄金数据对账、安全/可用性评测集、接口性能压测、Spark 数据规模
   扩展与决策效果示例。

## 1.4 创新点

1. **面向数仓语义的 Text-to-SQL**：以"主题识别→Schema 裁剪→语义+少样本→受约束 JSON 输出"
   减少字段幻觉；指标口径由字典统一提供，模型不猜测。
2. **四层 SQL 安全校验与至多一次修复**：字符串预检、JSqlParser 语法树、ADS 表白名单、
   LIMIT/时间条件资源约束，配合数据库只读账号构成纵深防御；失败反馈一次修复，
   杜绝无限循环，越权请求 100% 未得逞（实验见 8.3）。
3. **证据链驱动的智能分析**：结论必须引用真实查询结果的字段与数值，
   推测与事实分离（facts/possibleCauses），页面回显 SQL、行数、耗时与口径，
   并声明前后对比非因果推断。
4. **场景驱动可复现数据工程**：同种子同结果的事件生成、断点不丢不重采集、
   金额对账阻断发布、快照唯一活跃的发布机制，使论文实验完全可复现。
5. **指标快照决策闭环**：AI 只能创建草稿，人工审核锁定基线，执行后按目标方向
   评价效果，形成"发现—解释—行动—复盘"的完整业务循环。
