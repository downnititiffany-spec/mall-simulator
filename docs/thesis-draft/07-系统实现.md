## 7.1 前端实现（Vue 3 + ECharts）

七个页面：运营大盘（指标卡+销售/活跃趋势）、用户行为分析（漏斗+行为分布）、
商品分析（热度 TopN 条形图+明细表）、销售分析、数据流水线（一键演示 + run 列表 + 重试）、
决策中心（状态推进 + 评价展示）、AI 助手（问答 + 结果表 + SQL 证据折叠）。
前端只消费页面 DTO，指标口径/快照 ID/更新时间一律回显（§25.1）；
dev 代理 `/api`→8090，构建产物 `dist/` 可直接静态托管。
截图采集清单与采图惯例见 thesis-materials。

## 7.2 后端实现要点

1. **统一响应与错误**：`{code,message,data,traceId}`；写操作支持 Idempotency-Key；
   错误分类（TRANSIENT/CONFIGURATION/SCHEMA/DATA_QUALITY/SECURITY/RESOURCE/AI_FORMAT）；
2. **模拟时钟**（§20.3）：事件生成期间以"模拟业务时间"注入 EventClock（ThreadLocal），
   保证订单/行为事件时间轴一致、口径按 event_time 归属正确（曾因系统时间混入导致口径错乱，
   已回归修复并加测试）；
3. **Outbox 发布器**：定时轮询未发布事件 → 按小时滚动 JSON → 标记 published_at
   （at-least-once，DWD 去重兜底）；演示规模批次/周期可配（5000 行/3 秒）；
4. **断点采集**：文件级 checkpoint（next_offset 持久化）模拟 Taildir 语义，
   逐行契约校验（信封/版本/枚举/金额/payload 必要字段），坏行进隔离区并记索引；
5. **流水线**：7 阶段顺序执行器 + 幂等键（profile|code|time|version）+ 失败重试
   （attempt_no+1）；阶段记录输入输出/耗时/错误码；
6. **快照发布**：BUILDING→VERIFYING→ACTIVE 单事务切换（旧 ACTIVE→ARCHIVED），
   随后刷新 ADS 物化宽表（AI 白名单）；
7. **受控 Text-to-SQL**：四层校验 + 一次修复 + 只读执行（30s 超时/1000 行上限/金额字符串化）；
8. **决策**：12 态状态机；批准锁定基线（当前 ACTIVE 快照）；评价按目标方向取反分级。

## 7.3 关键实现验证（含教训）

| 实现点 | 设计 | 曾经踩坑（已修复+测试固化） |
|---|---|---|
| 业务时间 | EventClock 模拟时钟 | 订单事件用系统时间 → 口径错乱 |
| 生成确定性 | 每次 run 重置库存起点 | 跨 run 库存残留使同种子结果漂移 |
| 发布吞吐 | batch=5000/3s | 200/10s 时 3 万事件需 25 分钟 |
| SQL 层口径 | SQL 模板对象（可单测） | JSqlParser 4.9 API 迁移（SelectItem） |
| Spark 本地链 | 作业契约+链脚本 | 分区列重复定义/时间格式/derby 嵌套注释 |
