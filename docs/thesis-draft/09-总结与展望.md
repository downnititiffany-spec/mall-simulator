# 第九章 总结与展望（初稿）

## 9.1 工作总结

本文围绕"基于 Spark 大数据平台和智能分析模型的电商用户行为分析系统"完成设计、实现与实验验证，
主要工作可归纳为四条主线：

1. **可复现的数据工程**：Java 模拟商城与场景化生成器（11 类经营场景、同种子同结果）、
   事务 Outbox 与断点采集（暂停恢复不丢不重）、Hive 四层数仓（设计 DDL 29 张表；本地链由
   建表作业实建 32 张，含 8 张 `__staging` 孪生表）与 Scala Spark 作业链（11 个作业，
   建表→ODS→DWD→DWS→ADS）、快照版本化发布到 MySQL 指标服务库；
   全部口径由指标字典统一约束，金额对账失败阻断发布。
2. **可信的智能分析**：业务语义层 + 受控 Text-to-SQL（四层校验 + 至多一次修复）+
   证据约束结构化解释 + 规则降级，使 AI 在 ADS 白名单内回答问题并回显证据，
   模型不可用时主链路不受影响。
3. **可追踪的决策闭环**：AI 建议→人工审核（锁定基线）→执行→方向感知的效果评价，
   形成"发现—解释—行动—复盘"闭环，全程审计可查。
4. **多层次的实验验证**：黄金数据全链路对账（核心指标与人工标准答案完全一致、不一致项 0）、
   受控 Text-to-SQL 攻击集（7 项全部通过、拒绝记录 12 条）、固定看板 30 并发压测
   （P95 21~29ms、0 失败请求）、Spark 三档规模扩展、决策闭环运行状态（含样本不足判定）；
   实验环境指纹与数据已随系统归档可复现。

## 9.2 不足与改进方向

受实验环境限制，以下内容已设计并交付复现框架，但尚未形成实测数据，论文应如实表述为
"待环境执行"而非结论：集群规模（百万至亿级）的 Spark 分档性能、广播连接与并行度对照、
真实大模型的 Baseline A/B/C/D 消融（含令牌成本比较）、AI 数值事实一致率的人工评分。

此外，当前实现仍有可加强处：语义层的同义词覆盖依赖人工维护，可引入向量检索增强；
流水线的小时级调度为固定节奏，可接入 DolphinScheduler 表达复杂 DAG 与失败通知；
指标服务首版为 MySQL，Doris 仅作为第二阶段升级设想（当前未实现、未接入）。

## 9.3 展望

围绕本文的工程与实验基础，后续可在以下方向继续深化：

1. 计算升级：Spark 由本地验证平移至集群 YARN 模式，Flume 接管 Landing，
   数仓迁移由同一套作业（经平台流水线提交器）完成，补全百万至亿级性能对照；
2. 实时化：以 Kafka/SeaTunnel 与 Structured Streaming 补充小时级指标，
   与离线口径对账后形成"离线为权威、实时为近线"的指标体系；
3. 模型升级：语义层向量化检索、多模型路由（成本/质量权衡）、
   以"校验失败语料"持续精调提示词形成闭环优化；
4. 产品化：自定义报表、调度中心与外部告警，把"能看、能问、能做、能复盘"
   扩展到更大范围的运营团队。
