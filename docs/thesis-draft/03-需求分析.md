# 第三章 需求分析（初稿）

> 指标口径详细定义见 `docs/contracts/metric-dictionary.md`（15 项 v1）；
> 功能需求与 `docs/design/项目设计文稿 V2.2.md` §2.1 对应：十二个一级模块。

## 3.1 系统定位与目标用户

系统面向电商运营分析场景，服务五类角色：系统管理员（环境/凭据/权限）、
数据工程人员（采集/任务/数仓/质量）、数据分析人员（自助查询/报告）、
电商运营人员（大盘/趋势/商品/分层/决策）、答辩评审（全链路/性能/安全验证）。
建设目标：普通员工无需 SQL 即可"能看、能问、能做、能复盘"，同时保持
数据工程链路对技术人员的完全透明。

## 3.2 功能需求（十二模块概览）

| 模块 | 核心需求 | 对应交付 |
|---|---|---|
| 模拟商城 | 注册/商品/购物车/下单/支付/退款，事件随业务事务落 Outbox | mall-simulator 域名服务 |
| 数据生成 | 11 场景、规模/速率/种子/脏数据可配、可复现 | generator 引擎 |
| 连接与环境 | LOCAL/SINGLE_NODE/REMOTE_CLUSTER 三套运行配置，不写死节点 | 配置模板 + 文档（本地已实测，单节点/集群待环境） |
| 数据接入 | 断点采集、契约逐行校验、隔离与重放 | ingestion 模块 |
| 数仓流水线 | 8 阶段状态机、幂等键、失败恢复、补数 | pipeline 模块 |
| 数据质量 | 金额对账/去重/空值/枚举规则，失败阻断发布 | QualityChecker |
| 指标服务 | 指标字典、快照版本、唯一活跃、查询 API | metric 模块 |
| 经营分析 | 大盘/销售/商品/漏斗/活跃五视图 | analysis 模块 + 前端 |
| 用户与商品专题 | 分层（RFM 规则）、热度 TopN、转化明细 | spark-jobs 算法对象 |
| AI 辅助 | 语义层、受控问答、证据解释、审计、降级 | ai 模块 |
| 决策中心 | 12 态生命周期、基线锁定、效果评价 | decision 模块 |
| 系统与权限 | 演示权限（普通员工不可见技术配置）、凭据环境变量隔离 | 配置与文档 |

## 3.3 非功能需求与验收依据

| 类别 | 要求 | 验证方式（§27.3） |
|---|---|---|
| 正确性 | 金额对账误差<0.01、event_id 去重率 100%、核心黄金数据通过率 100% | 黄金夹具单测 + 真库黄金断言（`AnalysisGoldenMySqlIT`）/ 链路对账证据包 `20-reconciliation.tsv` |
| 安全性 | 危险 SQL 在生成阶段即被拒、AI 只读、凭据不入库 | 攻击集与安全问数实测（`.verify/r8-accept.ps1` → `r8-accept-report.json` D 组 5 条 / E 组 7 条） |
| 性能 | 看板 P95≤2 秒、30 并发、AI 问答≤30 秒 | perf-web-tier1.json（P95≤30ms） |
| 可用性 | 页面有状态反馈、错误可理解、AI 不可用主链路不受影响 | 降级模式实测 |
| 可复现 | 同种子同结果、实验含环境指纹与参数记录 | 生成确定性测试 + env-profile |

## 3.4 核心用例（节选）

1. 运营人员打开经营大盘 → 查看指标卡/趋势/漏斗 → 在 AI 助手中询问"转化漏斗各阶段人数"
   → 查看真实结果与 SQL 证据；
2. 运营人员基于 AI 建议"补充热销商品安全库存"创建决策草稿 → 提交审核 → 负责人批准
   （系统锁定当前 GMV 基线）→ 执行 → 按等长窗口评价效果（改善率 ≥5% 记 EFFECTIVE）；
3. 数据工程人员查看流水线实例（8 阶段明细）→ 对失败 run 修正数据后重试（attempt_no+1）；
4. 管理员查看快照版本（ACTIVE/ARCHIVED）与 AI 审计（问题/SQL/模型调用）→ 复核安全事件；
5. 演示评审：一键生成 3 天数据 → 端到端链路 → 黄金对账（`scripts/run-demo.ps1`）。
