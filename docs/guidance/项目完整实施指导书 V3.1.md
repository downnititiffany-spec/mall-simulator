## 1. 项目目标与本版范围

面向普通运营员工交付独立电商数据分析平台：来源可切换、采集和数仓自动运行、指标有统一口径、失败可定位和恢复、页面可读、AI 解释有可核查证据、决策由人工批准并评价。分析平台、参考商城、合成数据生成器继续作为三个边界清晰的程序；参考商城不是平台前置依赖，第二异构来源已经证明平台并非只能分析一个商城。

本版不是重写项目，也不是以「测试数量」代替产品验收。Doris、ClickHouse、DataX、AI 自动建仓、远程多节点高可用、真实外部商城接入均不纳入本版完成分母；保留扩展方向，须另立任务。论文正文与答辩材料在结果和学校要求冻结后集中编写，当前只保存真实问题、实验条件、性能原始值及边界。

## 4. 技术路线与边界

- 后端：Java 17、Spring Boot 3.2.5、MyBatis-Plus、Flyway；前端：Vue 3/Vite/ECharts；数仓：HDFS/Hive 表语义、Spark 3.5.1/Scala、ODS→DIM/DWD→DWS→ADS；服务库：MySQL 8 的 `analytics_meta` 与 `analytics_metric` 分责。3307 为当前隔离运行库，3306 不接触。
- 运行档分开标识：Windows `LOCAL` 小链、WSL 单节点 HDFS+Spark 小链、未来 `REMOTE_CLUSTER`。`local[1]` 加嵌入式 Derby 不等于共享 HMS，也不等于三节点高可用。
- 平台八阶段流水线保留现有契约。输入由同源 READY manifest 与独立消费台账决定，普通执行按最旧未消费批 FIFO；失败重试钉原批；全部已消费时 no-op 且不发布；显式重算必须指定目标批和原因；目标不可选时 fail-closed。发布前质量门只判断每规则/层最新结果，失败不切换 ACTIVE。
- AI 只能消费已发布 ADS/指标快照构成的 EvidencePackage；只读 SQL 受白名单/AST/成本/来源/快照约束。任何 AI 建议先 DRAFT，再人工审批，不自动改价、补货或发营销。模型凭据、脱敏范围和费用预算由用户/总控授权，不在文档或命令行留明文。
