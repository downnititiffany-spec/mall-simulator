## 2. 项目目标

课题延续“基于 Spark 大数据平台和智能分析模型的电商用户行为分析系统设计与实现”。

服务对象是普通运营员工、业务分析人员与数据管理员。员工应能够在网页选择授权商城来源和时间，查看销售、流量、转化、商品、用户等分析，理解数据质量与更新时间，获得有事实引用的 AI 解释，提交建议并跟踪效果；不要求员工登录虚拟机、手写 Spark SQL 或理解 HDFS 运维。

工程价值来自多来源适配、真实采集和数仓计算、指标一致性、任务可恢复与员工可用性。AI 是增强层，不是项目唯一工作量，也不能用“调用模型”替代真实分析链。

## 4. 最终系统范围

### 4.1 三程序边界

| 程序 | 必须负责 | 明确不负责 |
|---|---|---|
| 分析平台 analytics-server + web | 来源接入、数仓计算、质量、指标服务、分析、AI、决策、权限、任务反馈 | 商城交易、批量下单、直接改商城数据库 |
| 参考商城 mall-simulator + mall-frontend | 商品分类、订单、模拟支付退款、库存、事务 Outbox、人工演示 | 分析数仓、平台任务和批量生成计划 |
| synthetic-data-generator | 独立配置目标、随机场景、限速操作、文件夹具、运行统计 | 依赖商城内部 Java 类、直写商城业务表、嵌入平台 |

同仓库不等于耦合。平台在商城和生成器停止后仍可查询已发布快照。后续外部或开源商城通过数据协议和适配层接入，不复制另一套分析平台。

生成器保留 MALL_API 与 CANONICAL_EVENT_FILE 两种用途：前者验证业务交易路径，后者验证算法与坏数据；两者证据不能混称。丰富分类、价格、热度与场景是演示设计，不是每轮测试必须造数万商品。

### 4.2 首版产品范围

- 来源可配置；先贯通参考来源，再用异构字段/类型/枚举的小夹具证明来源可替换、ID 不串源。
- Landing → ODS → DIM/DWD → DWS → ADS → MySQL 指标服务，真实 Spark 作业和任务状态。
- 采集断点、可重放输入、质量阻断、失败保旧快照、受控重试与错误定位。
- 销售、行为漏斗、商品、用户/RFM、质量/运行、AI、决策页面以真实指标驱动；缺数据明确显示不可计算。
- AI 只消费稳定 ADS / 指标快照和由其构造的证据，不直接扫描原始 DWD，也不访问商城业务库、Landing/ODS。
- 五类决策方向：流量下降、漏斗流失、商品转化、库存风险、用户召回。缺库存或人群数据时不伪造建议依据。
- 管理员管理来源和连接，普通员工使用业务页面。接口存在不等于员工可用性完成。

### 4.3 后续优化与暂缓

“原第一阶段/第二阶段”是产品范围分组，不与本版八个开发阶段混用：原首版覆盖本版阶段 1–8 的首版交付；原第二阶段指首版之后的组件优化。

- 后续组件优化优先 DorisMetricStore；MySQL 为首版默认指标服务，Hive 保持数仓及显式降级设计。
- ClickHouse 只保留扩展契约方向，推迟，不与 Doris 同时落地；不声称具体实现类已存在。
- DataX、更多商城模板、可视化高级映射、Kafka/微批、外部调度器按收益另行立项，不为了技术数量堆栈。
- AI 辅助建仓仍是已接受的未来方向，但不作为阶段 6 的前置。它涉及源元数据/脱敏画像、蓝图、审批和 sandbox，与“AI 分析只读 ADS”区分；进入实际开发前由总控另发数据访问与任务边界，不借此打开 DWD 扫描权限。
- 不做真实支付、物流或完整商业商城；不训练大模型；不做无审批自动改价、下单、补货或营销触达。
- 不要求 WSL 模拟三个节点，不以单设备多进程声称物理容错或高可用。
- 项目完成前不提前写论文结论；过程可记录事实、实验配置、问题与解决方法。阶段 8 再统一形成论文和答辩材料。

## 5. 技术路线

| 层 | 技术与责任 |
|---|---|
| 后端 | Java 17、Spring Boot 3.2.5、MyBatis-Plus、Flyway；不改回 Python/FastAPI |
| 前端 | Vue 3、Vite 5、ECharts 5、Axios；分析与商城独立 |
| 采集 | 现有文件接入；Flume 完整链作为阶段 2/7 工作；DataX 后续 |
| 存储/数仓 | HDFS 存储、Hive 元数据及分层；Landing 不冒充 ODS |
| 计算 | Spark 3.5.1 / Scala 2.12，Spark SQL 负责清洗和指标 |
| 指标服务 | MySQL 8 默认；MetricStore 统一读取；Doris 后续 |
| AI | Java HTTP Provider、结构化输出、JSqlParser AST、证据包；模型失败可模板回退 |
| 测试 | Maven 管模块内选择，PowerShell 管跨模块/JDK调度；无根聚合 POM |
| 环境 | Windows 入口与 WSL2 可协作，远程集群可配置；测试 MySQL 3307，正式/历史 3306 冻结写入 |

Spark 测试固定显式 JDK8；后端默认/隔离档 JDK17。实际 Spark/Hive 部署的 JVM 兼容性另行验证，不把一个测试 JDK 结论扩展到所有环境。

总体链路：

```text
商城或外部来源 → 日志/导出 → LocalFile/Flume → Landing
→ ODS → DIM + DWD → DWS → ADS → MySQL 已发布快照
→ Spring Boot → Vue 分析 / AI 证据解释 / 决策跟踪
```

平台控制面负责连接配置、编排、状态、权限和审计，不在 Java 中重复实现一套假指标。HDFS 是文件系统，不是 MySQL 的直接 JDBC 替代品。MySQL/Hive 切换必须显式配置、校验同快照/同口径，不能自动按“数据大不大”随机选择。

## 7. 各阶段任务

### 阶段 1：开发基线与核心链路确认

1. 登记 HEAD、工作区、依赖版本、运行档案和本轮任务范围。
2. 引用已有 fresh 测试基线；环境变化才跑相关档位，不为文档发布重跑。
3. 选定隔离来源、runId、输入和预期输出；列出现有采集、Spark、发布、查询代码落点。
4. 用最小必要的业务冒烟确认下一切片可启动。无环境时先做纯函数/接口契约，不强制开集群。
5. 产出可执行工作包：允许文件、接口/字段、算法、验收、失败处理、反馈时点。

### 阶段 2：采集与数仓

1. 冻结来源身份和不可变映射版本；先做纯映射预览，再接采集，再做两源隔离。
2. 接入完成文件，不读取写入中的尾部；保留原文、标准化结果、隔离原因和批次。
3. Flume 建立 Spooling Directory → File Channel → HDFS Sink 小链；数据来源必须有日志/导出接口，不能“监听商城网页”。
4. 按设计的 ODS 四主题、DIM、DWD、DWS、ADS 模型补齐真实生产路径。
5. 验证重复、缺失、金额单位、时间格式、退款、迟到、重试和跨源同 ID。
6. 数仓 namespace/目录/连接由配置决定，不硬编码 node01–03。

### 阶段 3：指标计算

1. 对每个指标固定粒度、分子分母、时间窗口、金额/退款口径、空值规则和版本。
2. Spark SQL 计算销售、用户、商品、漏斗及质量专题，逐层对账。
3. 补分类/地区等尚无完整产出的专题；缺库存/成本不得生成利润或库存风险结论。
4. 导出 ADS 制品，核 schema、行数、checksum，MySQL 暂存验证后切 ACTIVE。
5. 只在同定义版本和同输入下核黄金值；宽松漏斗不得强制单调，比例不能直接按天平均。

### 阶段 4：查询与分析服务

1. MetricStore/专题服务返回明确 source、snapshot、definitionVersion、时间和质量信息。
2. 查询固定快照，不跨请求拼接不同 ACTIVE；归档读取授权、未知快照不静默回最新。
3. 异步任务返回标识，提供阶段/失败/重试反馈；分页、限流、超时统一。
4. 鉴权来自当前会话，拒绝伪造用户/来源；发布账号与只读查询账号分离。

### 阶段 5：页面

1. 经营概览、销售、行为、商品、RFM、AI、决策、运行/质量页接真实 API。
2. 页面统一加载/空数据/成功/失败状态，显示更新时间、来源、快照和限制。
3. 先做来源切换与关键业务阅读路径，再做美化，不把商城 UI 当毕业设计主工作量。
4. 普通员工不需操作 shell/SQL；管理员才配置连接与技术参数。
5. 前端统一测试入口属于 backlog，不妨碍用现有 npm test/build 与页面走查验证当前页面改动。

### 阶段 6：AI

1. EvidencePackage 从已发布指标构造事实、比较、维度、质量和限制。
2. 固定模板正常工作后接真实 Provider，记录真实 provider/model/prompt/耗时和失败，不以文字变化猜是否调用模型。
3. Text-to-SQL 仅限授权 ADS 单表安全查询，AST、成本、快照、日期、LIMIT与只读账号多层校验。
4. 六段解释与五类建议只能引用证据中的数字；非法输出/超时回模板并标明。
5. 决策必须先草稿后审批，效果评价采用等长窗口及可计算样本；不让模型直接执行商业动作。

### 阶段 7：业务联调

1. 独立生成器调用商城 HTTP，下单/支付/退款形成 Outbox 和日志。
2. 小规模串通采集→数仓→Spark→发布→页面→AI/决策；对账交易、事件、接收/隔离和指标不同量纲。
3. 第二来源异构夹具复用同一平台，证明字段适配及同 ID 不串源；真实外部商城按授权样例另验。
4. 检验源停机、重放、阶段失败、发布中断后旧快照仍读得到。
5. HDFS/Hive/集群验证按环境目标单独登记，不用 local[1] 测试替代。

### 阶段 8：部署与交付

1. 冻结实际部署拓扑、版本、端口、数据目录、服务账号、启动/停止及恢复步骤。
2. 按最终首版范围做一次可复现产品验收，总控判断通过、限定或未通过。
3. 整理正/负样本、真实链、界面和同环境实验；只有可复核基线才报告性能提升。
4. 在项目结果冻结后统一写论文、答辩材料与演示流程，明确模拟数据与真实来源、单机与集群边界。
5. 后续 Doris 对比不伪装成首版已实现能力；未交付项进入后续计划。

## 8. 各阶段完成标准

| 阶段 | 最小可验证完成标准 |
|---|---|
| 1 | 基线/档案/任务包明确；相应用例或必要冒烟可复现；无未知写入目标 |
| 2 | 原文到分层输出可追溯，重复可恢复，坏数据可定位；Flume/HDFS按实际测试边界报告 |
| 3 | 稳定指标公式、分层对账与发布制品；失败保旧；不靠前端/AI临时算出指标 |

| 5 | 员工能完成主要操作并理解结果；页面不混源/混快照；无数据不造数 |
| 6 | 真实调用与回退可区分，数值可追溯，安全拒绝有效，决策草稿及效果可验证 |
| 7 | 一个业务来源完整链及第二异构源链；日志/层表/指标/页面同源一致，故障样本通过 |
| 8 | 部署与范围验收由总控签收，论文/答辩只引用已证事实 |

## 9. Code Agent 工作权限

可以在下发工作包内修改业务代码、测试代码，运行必要测试，创建必要且脱敏的 evidence，维护 PROJECT_STATUS。每轮报告文件范围、结果、证据、未完成项、下一步；任务超过一个小切片应分步反馈，不等十几个小时才给结论。

不可以修改或自行升级指导书/设计文档、修改目标、扩大范围、改变架构、提升 backlog 优先级、自行宣布完整验收。新表/接口/调用关系等超出现有正式方案时先在状态文件提变更请求，由总控决定是否发布 V3.1。

可并行的典型任务：冻结 DTO 后的前后端、独立指标纯函数与 UI、独立模块测试。共享 POM、迁移号、规则目录、同一数据库、构建输出和重型 Spark 槽必须指定单一协调者。不得多个 Agent 共用 runId 或同时写同一分区。

## 10. 测试与验收规则

### 10.1 唯一项目级入口

`scripts/run-tests.ps1`。档位正式名称与实际 CLI 参数区分：

| 档位名称 | 参数 | fresh 基线 | 环境/成功口径 |
|---|---|---|---|
| default-tests | -Suite default | analytics 632 + mall 13 + generator 106 = **751** | JDK17；逐模块计数，F/E为0，正常退出 |
| isolated-tests | -Suite isolated | mall 30 + generator 19 + metric-analysis IT 6 = **55** | 3307、新runId；不计依赖构建的common 89 |
| spark-tests | -Suite spark | **111** | JDK8、ScalaTest；本轮新写 TestSuite.txt |
| all-tests | -Suite all | 顺序 default → isolated → spark | 任一档失败或0 tests整体失败 |

数字来源：2026-09-15 fresh 证据 `docs/acceptance/dev003c-unified-test-entry-20260915/`；本轮读取核对，不是重新执行。751/55/111是三个边界不同的集合，不合称全部功能验收。

Spark 只认 TestSuite.txt 的实跑数、failed/aborted、All tests passed 与报告新鲜性；Surefire 的 Tests run:0/BUILD SUCCESS 不能替代 ScalaTest 成功。**spark local[1] + in-memory catalog 测试通过 ≠ 生产 Hive / Spark 集群验收通过。**

隔离/all需要显式 Confirm、允许实例、受限账号与新runId。禁止3306写入；不使用root跑应用/IT。AllowCountDrift仅总控批准基线变化后使用，不能为绿灯放宽。默认档不连接外部数据库。

### 10.2 开发提速

- 普通改动先跑受影响单测；跨模块边界再 default；数据库改动跑 relevant isolated；Spark 算法改动跑 spark。
- 55条黄金验证语义，1000条验证轻量串链；大规模/性能/集群实验集中到阶段性需要，不每改一行重跑。
- all是整合检查，不是每次编辑必跑；前端当前可用模块自己的npm test/build，统一入口后置。
- 不删关键负例或伪造成功。零用例、未启动、缺配置均不能记通过；测试被排除必须明示。
- 四个结论独立：代码实现、测试通过、限定实链、完整验收。只有总控决定最后一项。
