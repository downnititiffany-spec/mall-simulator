## 2. 项目为什么做

课题延续“基于 Spark 大数据平台和智能分析模型的电商用户行为分析系统设计与实现”。目标用户是普通运营员工、业务分析人员和负责数据接入的管理员。

项目解决五个实际问题：

1. 商城订单、支付、退款、行为和商品信息分散，人工汇总慢且口径容易不一致。
2. 大数据工具通常要求写 SQL、运行脚本，普通员工无法直接使用。
3. 商城更换后字段、枚举、标识和时区不同，原有分析流程容易失效。
4. 页面数字缺少可追踪的来源，异常数据可能被当成经营变化。
5. 只有图表或 AI 文本，不能形成“发现问题—核查证据—人工决策—效果回看”的闭环。

因此交付物是一个可使用、可切换来源、有前后端的分析产品，不是几个虚拟机脚本的集合；商城和生成器只是独立数据来源与验证工具，不是系统主角。

## 3. 最终产品和三个程序的责任

| 程序 | 负责 | 不负责 |
|---|---|---|
| 分析平台 analytics-server + web | 接入、标准化、数仓任务、质量、指标、AI、决策、报告、权限和运行反馈 | 经营商城、替商城下单、直接修改商城订单或库存 |
| 参考商城 mall-simulator + mall-frontend | 商品、购物车、订单、模拟支付退款、业务事件 Outbox | 数仓、分析平台元数据、AI 分析、批量造数 |
| 独立生成器 synthetic-data-generator | 场景计划、限速随机操作、HTTP 商城适配、契约文件夹具、运行统计 | 依赖商城内部服务类、直接写商城业务库、触发平台内部 ETL |

三个程序可以暂时位于同一代码仓库，但必须独立启动、配置、鉴权、持久化和失败。平台在商城/生成器停止后仍能查询已发布指标。平台不能依赖固定的 mock-mall、node01–03、某个磁盘目录或开源商城的数据表结构。

第一种造数模式 MALL_API 用适配器调用商城公开 API，验证真实业务路径。第二种 CANONICAL_EVENT_FILE 产生契约夹具，适合算法、脏数据和故障测试；它不能冒充真实商城接入。后续开源商城同样通过适配器与映射接入，不复制第二套分析系统。

## 4. 第一阶段、第二阶段和暂缓范围

### 4.1 第一阶段：可用的分析产品

第一阶段分两个工程出口，避免把“已有最短链路”误写为“所有规划完成”。

**出口 A：核心可用。**

- 三程序独立，参考商城能够人工操作；生成器可以独立执行有商品差异和经营场景的计划。
- 一个来源可以从采集、Landing、ODS、DIM、DWD、DWS、ADS走到 MySQL 已发布指标和员工页面。
- 真实异步 Spark 执行、任务状态、日志、幂等、恢复、质量失败保留旧快照。
- MySQL 默认指标服务；Hive 保留数仓角色和受控降级查询设计，不按数据量随机切换。
- 销售、行为、商品、用户、质量和决策页面有真实数据来源，空数据如实说明。
- AI 不可用时固定分析正常；真实模型接入、证据解释、安全问数和五类决策按各自验收完成，不能只验 Mock。
- 隔离实例和测试门禁可用，不以正式库作为开发试验场。

**出口 B：多来源可替换。**

- 新来源登记、不可变映射、预览与激活流程完整。
- 第二个字段、类型、枚举和 ID 均不同的来源完成同一分析链。
- 相同外部 ID 不串源；缺失数据被隔离或显示不可计算，不悄悄补零。
- 第一阶段最小第二来源允许用异构文件夹具；真实第三方商城是另一种证据等级，未接入不能宣称已支持某开源商城。
- 分类/地区等既有专题补齐数据和页面；不是继续扩张任意 ADS 表数量。
- 员工能够选择授权来源、查看时间口径、理解异常、提交决策。

### 4.2 AI 辅助建仓：已接受的 V2 系列独立出口

AI 建仓不是取消项，也不是第一条可用链的前置。顺序是：人工确定性映射 P5 先完成，再交付 AI 映射助手、数仓蓝图、规则校验、受控编译、sandbox、审批、发布与回滚。

系统固定用户、商品、行为、订单、支付、退款核心模型，允许源扩展。AI 提建议，程序校验并执行已批准的结构化计划；禁止模型自由执行 DDL、SQL 或 shell。AI 建仓是否必须计入本次学校论文/答辩必交范围，仍需学校期限和用户最终取舍，见 §11；在此之前不得将“已接受的工程方向”降为取消。

### 4.3 第二阶段：有收益的组件优化

优先实现 DorisMetricStore，使用同输入、同口径、同快照比较 MySQL 与 Doris 的正确性、延迟、资源占用与维护成本。

其他可立项方向：DataX 结构化表同步；更完整的可视化字段映射和多商城模板；增量与迟到补算；按资源评估分钟级微批；需要时接入 Livy 或 DolphinScheduler。它们不是为了堆叠软件数量而全部强制实现。

### 4.4 明确暂缓或不做

- ClickHouse 当前只保留接口/能力矩阵，不与 Doris 同时落地。
- Kafka、SeaTunnel、Structured Streaming、秒级实时、多租户跨商城合并分析后置。
- 不训练大模型，不要求本机安装本地大模型或额外 AI harness。
- 不做真实支付、物流、完整商业商城；不让商城美化占用分析主线。
- 不做无审批自动改价、补货、营销触达；决策系统只提供建议、流程和评价。
- 不以 WSL 的多个进程或多个虚拟节点声称真实多服务器高可用。
- 不以每日百万/千万数据全链压测作为普通修改门槛。
- 不清理历史库、checkpoint 副本、旧 worktree 或用户文件；删除需独立授权。
- 当前不写论文正文、答辩稿或扩大 PPT。仅记录可验证事实和实验元信息。

### 5.1 WSL 与集群定位

最新记录中的已确认定位为：WSL2 是主要本地开发环境，可承载开发依赖和隔离服务；VMware 三节点仍作为已有集群验证目标。WSL 内不复制三节点集群，不承担正式集群计算；可使用单节点 HDFS/Metastore/Spark 小样本验证兼容性，但不得把它与集群性能/容错验收等同。

旧 V2.5 把“完整 WSL 单节点数据栈”写为主验收路径，09-14 12:20 后的授权记录调整了该定位。当前过渡路线是“宿主机应用 + WSL 隔离 MySQL 3307”。是否必须把完整 WSL 单节点数据链列为首版独立强制验收门，仍列为 G-01，不能因这一点阻塞纯函数或安全隔离开发。

资源采用已批准的 4 vCPU、8 GB RAM、4 GB swap。12 GB 仅为不足后的备选，不写成已配置。HDFS、Metastore、缓存、临时数据放 Linux ext4，不复用 Windows Hadoop 路径。现有已安装版本不因文档更新自动升级。

### 5.2 不绑定主机

SourceRegistry 管来源身份，RuntimeProfile 管执行连接，MetricStore 管指标服务。环境切换不修改业务算法；SSH 只是远程提交方式之一，不是所有配置的必选项。云端或其他集群通过新档案接入。新档案先做连接和权限预检，运行冻结配置，切换不得使在途任务改变来源或目标库。

## 6. 总体架构和数仓定位

```text
独立生成器 --公开 HTTP--> 可替换商城 --Outbox/日志-->
采集适配器 --原始 Landing + 映射/隔离-->
Hive ODS -> DIM/DWD -> DWS -> ADS
     -> 质量门 -> 发布制品 -> MySQL 指标快照
     -> 分析平台 API -> 员工页面 / AI 证据解释 / 决策评价

RuntimeProfile：配置执行环境
SourceRegistry + 版本化映射：配置来源语义
```

HDFS 是文件存储；Hive 管库表、分区与数仓语义；Spark 执行转换计算；MySQL 指标库服务频繁的页面查询。MySQL 不是替代 Hive 的数仓，也不是第五层。即使以单机运行，分层、口径、血缘和版本仍是数仓设计，只是不具备物理多机容错。

平台采用模块化单体，不为毕业设计引入微服务运维负担。异步任务由后端编排，用户不手写 Spark 命令。模块名称、端口、库名和具体数据结构见设计文档，本指导书不维护第二份字段清单。

## 8. 验收标准与完成定义

### 8.1 必须通过的产品验收

1. 用户仅用 Web 完成授权来源选择、经营查询、异常核查、AI 建议阅读、决策提交和效果查看。
2. 参考商城停止不影响既有指标读取；生成器停止不影响分析；无模型时固定分析可用。
3. 新数据能被自动/手动触发的采集和异步任务处理，不依赖开发者手工改 SQL。
4. 相同输入重跑数值稳定；重复提交不重复发布；故障从合法阶段恢复。
5. 每条阻断规则都有“失败→不产生新 ACTIVE→旧 ACTIVE 内容不变”的负例。
6. 同一 snapshotId 下 Hive/导出/MySQL/API/页面/AI 的对应数字一致；不能把不同运行混在同一验收表。
7. 第二来源异构夹具全链成功，且同 ID 不串数据。真实外部商城接入另记证据，不虚报。
8. 安全测试能拒绝越权、危险 SQL、提示注入、越界路径和正式库写入；正常用例也必须能通过，不能靠“全部拒绝”取巧。

### 8.2 测试和性能目标

- 金额使用精确十进制，订单行金额误差严格小于 0.01；不随浮点误差任意放宽。
- 黄金数据全部必须通过。55 条黄金与其他历史夹具不是同一个版本，必须带输入 hash。
- 功能回归用最小覆盖样本；里程碑可用约 1000 条；10万/百万以上只做专门性能实验，资源允许且有明确问题再运行。
- 看板 P95≤2s、状态查询≤1s、AI 约30s 超时降级均为目标，不是当前成绩。并发目标需固定机器、数据、请求混合、冷/热缓存和测量窗口。
- 真实 LLM 评测将 SQL 可解析、执行成功、结果正确、安全拒绝、事实一致和耗时分开统计。
- “退出码0但运行0测试”“前序依赖失败导致模块 SKIPPED”“Mock成功”都不算对应真实验收成功。

### 8.3 证据分级

设计通过、代码存在、测试通过、限定真实验收、完整产品验收是不同状态。每个完成声明带采样时点、代码或文件指纹、环境、数据版本、实际断言及未覆盖范围。HTTP 200、jar存在、表存在均不能单独证明业务正确。

历史 269 条的 132完成/90部分/42未做/5不适用是旧快照；后续229项或139项审计不能直接替换其分母。当前不公布未经统一归并的新完成率。
