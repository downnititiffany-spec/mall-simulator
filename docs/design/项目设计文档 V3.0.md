## 1. 使用约定

本文件回答“怎样实现”，指导书回答“要不要做”，PROJECT_STATUS回答“现在做到哪里”。README只是入口。V2.x及历史看板/证据/契约原地只读，不改旧路径；重要有效约束在本文件重述，不要求开发者从旧日志猜方案。

表述级别：

- **当前实现**：当前源码存在的类、接口、配置或迁移，不等于全部场景已验收。
- **历史限定证据**：某个输入、环境、代码/制品指纹下曾通过。
- **设计目标/待开发**：后续工作约束，不声明已经落库或可以调用。
- **backlog**：非当前开发前置，只有总控能提升优先级。

第3–16章中的新增字段、算法增强、映射/AIW接口按目标解释；明确标为现有的部分才是现有实现。不把表结构清单当所有表都已有生产数据。公开接口族是代码导航与语义边界，不能据此跳过对应Controller DTO校核。本轮不运行应用、测试或数据库探针；测试数来自已入库fresh证据的只读复核。

## 3. 总体架构和代码结构

### 3.1 分层

```text
业务生产面：商城 <-HTTP- 独立生成器
交换边界：业务日志 / 标准事件 / manifest（版本化）
数据面：Landing -> ODS -> DIM+DWD -> DWS -> ADS -> 发布制品
控制面：SourceRegistry + RuntimeProfile + PipelineService + 质量/发布/恢复
服务面：MySQL MetricStore -> REST -> 分析Vue页面、AI、决策
```

控制面不代算业务指标；指标算法在Spark/版本化指标层，不使用Java“假计算器”替代真实ADS。页面和AI不直读商城业务库。

### 3.2 平台六个模块

| Maven模块 | 现有职责/代码锚点 | 输入→输出 | 待补重点 |
|---|---|---|---|
| platform-common | 公共DTO/错误码、WarehouseNamespace、MetricStore契约、质量规则公共类型 | 类型/契约→共享约束 | 跨模块同规则一致，不引入商城业务类 |
| connection-ingestion | RuntimeProfile、SourceRegistry、LocalFileIngestor、LandingStorage | 源配置/文件→批次/manifest | 通用Connector、确定性Mapper、Flume编排 |
| warehouse-pipeline | PipelineService、JobSubmitter、JobCommandBuilder、质量门 | 批次/档案→异步Spark阶段 | 配置冻结、恢复、SINGLE_NODE、质量版本 |

### 3.3 依赖纪律

平台不得依赖mall-simulator或generator的实现jar；生成器不得依赖MallBusinessService。交换协议用JSON/HTTP，不跨库查询。公共契约不含某商城数据库实体。每个客户端有连接/请求超时、有限重试、幂等与错误映射。

## 6. 独立商城与数据生成器

### 6.1 商城业务模型

| 实体 | 最小字段 | 规则 |
|---|---|---|
| 商品/分类 | productId、categoryId、name、price、cost、stock、status、version | 价格用decimal；cost缺失时不算利润；库存更新做乐观锁/事务 |
| 用户 | userId、registeredAt、region、memberLevel | 只生成模拟标识和非敏感画像，不需要真实电话/身份证 |
| 订单头 | orderId、userId、status、orderAmount、paidAmount、createdAt、paidAt | 状态按中立契约流转；取消不能再正常支付 |
| 订单行 | orderId、productId、quantity、unitPrice、lineDiscount | 数量正整数；金额精确计算 |
| 支付/退款 | paymentId/refundId、orderId、amount、status、eventTime | 模拟支付；退款成功才冲减，累计不超过实付 |
| event_outbox | eventId、eventType、aggregateId、payload、createdAt、publishStatus | 与业务变更同事务写入，发布至少一次，下游幂等 |

商城负责“按自身规则完成一笔交易”；平台只消费其提供的数据。不能要求每个外部商城改成参考商城数据库结构。公开商城API失败、库存不足、重复请求应给业务码，由MallTargetAdapter翻译生成器结果，平台不复制商城错误码全集。

### 6.2 生成器五类元数据

现有generator_meta中五表已有记录，不得再写“生成器元数据表未建”。目标列级一致性仍需检查。

| 表/结构 | 核心内容 | 约束 |
|---|---|---|
| generator_target | 目标URL、adapterCode、credentialRef、能力、状态 | 不存平台DB连接；目标停用时不发请求 |
| generation_plan | planId、version、mode、seed、timeWindow、rate、用户/商品/场景参数 | 启动冻结plan版本；不可用能力提前拒绝 |
| generation_run | runId、planVersion、status、startedAt、counts、failure | STOPPING需停止新派发并结算在途 |
| generation_artifact | runId、URI、checksum、recordCount、contractVersion | 文件模式制品可重放；与采集manifest不同 |
| generation_event_stat | runId、eventType、accepted/rejected/count等 | API成功数、事件数、订单数不同量纲，不能相互代替 |

目标接口职责：MallTargetAdapter负责discover/probe、catalog读取及用户/购物车/下单/支付/退款操作；PlanCompiler验证场景和能力；ScenarioRegistry提供版本化场景；GenerationRunService调度；FileModeGenerationEngine生成文件。现有具体签名沿实现制品校验，不因本章补充语义而擅改调用方。

每次请求使用稳定业务幂等键（runId+virtualUser+logicalActionIndex），只重试可重试错误；超时结果不明时先查订单状态或使用商城幂等API，不能当作“未下单”重复扣库存。外部商城不具备某能力则报告UNSUPPORTED，不伪造成功。

### 6.3 商品与用户分布算法

- 商品目录演示目标可用8–12个一级分类、每类5–15个二级分类、500–5000商品；不是每次测试必须造这么多。黄金测试只保留覆盖分类/价格/库存边界的小集合。
- 分类价格用截断对数正态分布，在配置的min/max内采样；金额转BigDecimal并按约定保留两位。成本可按价格乘区间系数生成，但不得据此声称真实毛利。
- 商品受欢迎程度使用Zipf权重，指数候选0.8–1.2，配置版本固定。分类偏好、价格敏感度、时段活跃权重共同决定选择概率。
- 行为采用有状态转移：浏览→收藏/加购→下单→支付→可选退款；不把事件类型独立随机抽取导致支付先于订单。
- 根seed拆成用户/商品/场景/时间子流，使线程数变化不会改变文件模式的逻辑样本；固定序列化和排序后才可声称字节复现。
- MALL_API受服务器分配ID、并发、真实时钟和库存影响；同seed不保证返回字节相同。应固定初始状态与逻辑时钟，并比较规范化事件/经营汇总，记录非确定性来源。

### 6.4 场景、执行和UI

保留normal、promotion、weekend_growth、sales_decline、refund_rise、price_increase、hot_product、stock_shortage、new_product_cold_start、old_user_churn、new_user_growth等现有场景方向。每个场景记录作用窗口、受影响商品/人群、概率或价格参数变化、限速和expectedEffect。expectedEffect只供独立验收oracle，不发送给AI作为“答案”。

生成器页面：目标管理→计划参数/能力检查→场景预览→启动/停止→成功失败/事件统计→制品下载。数据清理需独立隔离检查，不和“启动计划”绑定。文件模式可加入缺失、非法枚举、重复、乱序、迟到、金额错误和恶意文本；MALL_API模式不得绕过商城业务规则硬写脏订单。

### 6.5 独立性验收

商城关闭时生成器报告目标不可用，不写商城数据库；平台仍读旧指标。生成器关闭时商城仍可人工下单。第二MallTargetAdapter至少验证协议/字段差异；第二分析来源夹具不是第二商城HTTP适配器，两者不能互相替代。

## 7. 来源登记和确定性字段映射

### 7.1 身份唯一所有者

source_registry为源登记：id、source_code、display_name、ingest_mode、profile_path、timezone、currency、status、profile_version、warehouse_prefix及时间字段。source_code创建后不改；当前FILE实现，JDBC/HTTP预留且不显示可用。

读层兼容DRAFT/ACTIVE/PAUSED/DISABLED，现有写层DRAFT/ACTIVE/PAUSED；当前选择来源由激活runtime_profile.source_id表达，不新增另一套is_current。warehouse_prefix归源登记，非空且合法；runtime_profile旧prefix列只断读不默认删除。源画像只管语义，不存密钥。

外部event/order/user/product/refund标识按原始字符串保存，不能去掉U/P前缀、前导零或强转Long。去重和代理键作用域包括sourceId；HASH64使用已冻结的统一契约和测试向量，不另造hash实现，null必须定型，碰撞检测与反查策略需保留。

### 7.2 映射版本与存储载体

现有源画像是analytics-server/source-profiles中的版本文件。历史资料同时规划schema_mapping/source_profile等表，但不得既写文件又写DB形成两个owner。首版继续文件为不可变画像内容，DB登记引用与版本；未来确需数据库编辑发布时由新设计版本给迁移、唯一内容owner及回滚。本文中的MappingProfile等是逻辑结构，不代表已经建表。

MappingProfile最小字段：profileVersion、sourceCode、contractVersion、checksum、eventTypeMappings、按事件类型分组的fieldMappings、enumSemantics、timePolicy、amountPolicy、required策略。运行manifest记录版本+完整checksum。新语法先冻结再实现；不得就地改变旧profile语义。

### 7.3 映射执行器14条规则

1. **契约先行**：先把当前事件Markdown与JSON Schema差异收敛为明确语义。现有canonical-event.v1是机器投影，source_system非固定mock-mall。扩展字段可先做兼容可选项，是否升主版本由破坏性判断，不只为改文档升级。
2. **映射方向**：sourcePath→targetPath；按eventType分组，显式区分envelope与payload。同组两个来源写同一目标时profile无效；不同事件组可复用字段名。
3. **保留扩展**：@keep按原始叶子名称保留扩展，撞canonical字段或其他扩展则拒绝。原始完整JSON另存，不能把“保留部分扩展”当成原文保真。
4. **时间**：timePolicy.field指源字段，先按有序formats逐个严格匹配，第一个成功格式生效；epoch秒/毫秒必须声明。使用IANA时区，DST跳空/重叠拒绝并待确认。保留原时间文本和规范化值。
5. **缺失**：必填缺键/null/trim空白均EMPTY_FIELD，detail区分MISSING/NULL/BLANK。可选缺失可省略并计数；显式null只在nullable允许，否则按已声明OMIT策略计数；不隐式补0。
6. **错误码**：保留EMPTY_FIELD、DUPLICATE_EVENT、BAD_ENUM、BAD_AMOUNT、FUTURE_TIME、BAD_TIME_FORMAT、UNSUPPORTED_SCHEMA_VERSION；新增PROFILE_INVALID、PROFILE_VERSION、JSON_PARSE_ERROR、UNKNOWN_EVENT_TYPE、TYPE_MISMATCH、ENUM_UNRESOLVED、TIME_AMBIGUOUS_LOCAL。别名仅兼容翻译，不能重写历史错误行。
7. **金额**：从JSON数字原词或字符串解析BigDecimal。声明FEN/YUAN，目标元字段FEN÷100；分应为整数；两位金额使用精确舍入规则，不接受隐式double和任意倍率。负值按字段契约拒绝。
8. **原始/标准化隔离**：raw记录全部输入；canonical只保存通过转换的数据，单独checksum。eventId来自稳定业务标识，不用随机UUID或整行hash冒充原事件ID。缺稳定ID应隔离并问源方。
9. **路径和数组**：只允许对象路径和固定数组下标，不支持任意递归、通配执行或脚本。ITEM_MAP保持元素顺序和数量；任一必填订单项失败则整事件隔离，禁止只留下成功几项改变订单金额。
10. **dry-run**：最多100条受控脱敏样本，sampleRef只能引用平台批准的位置，不任意URL/本机路径。输出转换预览、行数、覆盖率、原因和版本；不写正式数据/checkpoint/激活指针。
11. **三步交付**：a纯映射/预览；b采集/双manifest/重放；c两源数仓/指标。不得一口气重写所有层后再验证。
12. **枚举**：声明null表示观察到但语义未决，保留warning；关键字段未决禁止激活。可选nullable可按契约保留null并警告。完全没登记的值为BAD_ENUM，不用“未知=成功”吞掉。
13. **统计**：requiredCoverage=成功必填位置/总必填位置；enumCoverage按观察到的字段路径+原始枚举去重计算有效映射比例；分母0为null。reasonCounts按违例计可大于隔离行数；系统异常不冒充坏数据。
14. **身份与发布**：预览与激活比对profile内容hash；运行冻结同一版本。使用已有统一测试入口及当前模块测试验证，不再以收编所有历史IT为前置；不删旧manifests来制造绿色测试。

## 8. 采集、Flume和Landing

### 8.1 数据流

正常业务路径：生成器HTTP→商城事务+Outbox→滚动日志→完成文件→Flume或LocalFile采集→原始Landing→版本映射→canonical/隔离→manifest→Spark。人工下单同一路径。文件夹具从独立受控导入口进入，标明fixture来源。

Flume不“监听任意商城网页”；必须有受支持日志、导出、消息或同步来源。接开源商城先确认可读数据边界和许可证/脱敏，再做适配。

### 8.2 Flume首版链路

首个完整集成目标采用Spooling Directory Source + File Channel + HDFS Sink：

1. 生产者写临时文件；写完flush/close后原子改名或移动到spool，文件名全局不复用。
2. File Channel的checkpoint/data目录分离并持久化，异常重启可恢复。
3. Sink写source级Landing原始区，按采集日期/小时组织。未提供event_type header时不能使用它拼路径。
4. Sink in-use临时文件不参与manifest；只枚举已完成文件。
5. Flume至少一次传输，平台必须去重、记录文件offset/hash和批次计数；不承诺端到端exactly-once。
6. Windows商城→WSL spool需要明确文件传输/交接方式，不能默认Linux能无代价直接读任何Windows目录。

现有LOCAL残行等待和Taildir式断点语义继续适用其既有实现；不得把Flume目标Spooldir与运行中的文件尾读混写成同一种配置。Taildir可作为后续单独连接器。每个源至少显示接收时间、积压、已采断点、隔离数、最新批次和错误，不探测生产者就不能断言“商城在线”。

### 8.3 连接器与存储接口

| 抽象 | 输入/返回 | 实现注意 |
|---|---|---|
| SourceConnector（目标） | source+冻结配置→probe/发现文件/采集批次 | FILE/Flume先做；DataX/HTTP等未实现明确拒绝 |
| LandingStorage（已有） | namespace、exists/list/open/stat、writeManifest、healthCheck | local/HDFS职责一致，不传hdfs URI给java.nio.Files |
| HdfsLandingStorage（已有） | Hadoop FileSystem API | 不是待新建类；需验证依赖打包、路径越界、客户端关闭、写清单覆盖策略和实例权限 |
| Mapper（目标） | raw+mapping→canonical或quarantine | 纯转换与持久化分离，供dry-run与真实采集共用 |
| BatchCompiler（目标接线） | 完成文件+统计→immutable manifest | 原文/标准化分别引用hash，完成后提交checkpoint |

HDFS客户端依赖若provided，Boot运行时需真实提供对应jar；仅设置环境变量不能保证Java classpath已加载。HDFS探针应只访问获授权根而不是要求列整个“/”。

### 8.4 目录、批次与checkpoint

目标逻辑目录：source/raw/ingestDate/batch；source/canonical/mappingVersion/batch；source/quarantine/batch；source/manifests/batch.json。实际前缀来自档案，source目录名必须经过安全编码和白名单。输出使用临时文件+完成标识，已有批次号冲突但hash不同应报错，不能覆盖。

manifest包含batchId、sourceId/sourceCode、contractVersion、profileVersion/hash、raw/canonical URI与各自checksum、时间窗口、总/接收/隔离/重复数、文件长度和offset、创建者/时间。文件生产制品清单与平台采集清单独立；新可选字段兼容旧ingestion-manifest.v1，必填/行为变化需显式升级。

LocalFileIngestor.checkpointKey/canonical是路径规范化唯一owner；读取历史键也用同规则。checkpointFiles表示当前events目录已建断点的文件数，pendingFiles为同次扫描目录文件总数；newFileCount现定义为仍有可采完整行的文件数，不是刚出现的文件数。残行等换行后再消费。库中历史“\\.\\”副本不在本轮删除范围。

无新数据返回noNewData=true和零新增记录，但这不证明上游持续在线。成功提交水位采用左闭右开窗口；失败不推进，重试同批次幂等。并发采集需要source级租约或唯一批次约束，避免两worker读同一offset各发布一份。

### 9.4 交易和维度算法

订单事件按业务标识分组，以event_time、ingest_time、event_id确定稳定顺序；状态机非法跃迁隔离，不直接“取最后一行”绕过业务。去重同序键仍冲突时用冻结输入位置做稳定仲裁并记冲突，不依赖分区执行顺序。

订单行核对SUM(quantity×unit_price−line_discount)=order_amount，绝对误差<0.01。付款金额与订单金额另检；退款按source+refundId取最新成功状态再按订单累计，累计≤实付。不得重复重放累加退款两次。

代理键由统一HASH64契约输出BIGINT，空键显式CAST(NULL AS BIGINT)。插入采用列名/类型对齐并验证运行时schema，不能只改一个NULL表达式就认定根因已消除。旧user_key STRING→BIGINT事故表明SELECT顺序、表schema、实际jar指纹必须一起取证。

### 9.5 存储与增量

目标使用列式Parquet/受支持压缩、日分区dt=yyyyMMdd，ODS按需要小时分区；实际codec要从产物检查，不能仅引用历史README“全Snappy”。Spark local也能访问HDFS，文件存储和执行manager是两个配置轴。

迟到数据按事件归属日进入可追踪补算计划；水位成功后推进。重跑写run/snapshot专属临时分区，验证后发布，旧快照保留。分区裁剪、小维表受阈值广播、复用中间结果、必要的小文件合并都应先测后用，不能无条件cache或repartition(1)。

### 10.3 JobSubmitter与运行数据

现有LocalProcess/Ssh提交器负责submit/poll/cancel/log引用，不计算业务。提交返回任务ID不等于完成；externalJobId是进程标识或集群应用ID，需记录kind/host/startedAt以防PID复用。

pipeline_run最少记录runId、idempotencyKey/requestHash、sourceId、runtimeProfileId/version、businessWindow、inputVersion、outputSnapshotId、status、attempt、timestamps。pipeline_stage_run记录stageCode、状态、开始结束、输入/输出引用、错误、重试。spark_job_run记录jobCode、externalJobId、artifactHash、exitCode、logsURI、计数和应用终态。

目标异步流程：校验请求/权限→事务创建run和幂等约束→返回taskId→有界执行器领取→按DAG提交→持续更新阶段→质量与发布→终态。不能在HTTP请求线程串行等待整条Spark链。应用重启后根据数据库运行状态和外部作业状态恢复，不能所有RUNNING直接改成功。

### 10.4 幂等、恢复和调度

- 同幂等键同请求返回原taskId；同键不同输入返回冲突，不覆盖原run。
- retry可跳过成功阶段的前提是输出仍存在、source/profile/输入/规则/代码指纹仍匹配；否则从首个失效阶段重算。
- 临时输出用run/attempt/snapshot隔离；重试不覆盖他人分区；清理只针对本run可证明所有的临时根。
- 网络瞬态可有限重试（默认上限2次目标）；schema、参数、权限、业务质量失败不能无条件重试。
- 取消要停止后续派发、请求cancel并等待外部状态；无法确认记UNKNOWN/需人工检查，不写CANCELLED成功。
- 定时器只触发同一应用服务；默认开发按需手动启动。启用小时/日任务时固定时区和左闭右开窗口，租约/唯一键避免重复调度。迟到补算单独任务，不直接改已发布快照。
- 运行中心展示最近反馈、阶段耗时、日志尾部和失败建议；长期无心跳标“待核实”，不自动删除现场。

## 11. 指标体系、算法和业务专题

### 11.1 统一指标结构

MetricDefinition：metricCode、名称、单位、公式、数据粒度、时间字段、过滤条件、分子/分母、zeroPolicy、direction、definitionVersion、lineage。MetricValue：source作用域、snapshotId、businessDate/窗口、dimensionKey、metricCode、decimalValue、definitionVersion、qualityStatus、warnings。

中文名/别名用于交互，不产生另一公式。v1/v2退款定义需显式版本；sale_amount等内部列名与gmv展示编码使用唯一映射。空分母为null，显示“无可计算数据”，不能0%或无穷。UV等distinct指标不能简单累加每日值计算整月UV。

### 11.2 核心公式

| 指标 | 计算约束 | 输出用途 |
|---|---|---|
| PV | 有效view事件数 | 流量 |
| UV | 观察窗口浏览用户按source+user去重 | 流量/转化分母 |
| DAU | 当日有效行为用户去重 | 活跃趋势 |
| 收藏/加购 | 对应行为事件数，用户转化时另算去重用户数 | 行为 |
| 支付订单数 | 有效支付订单按source+order去重 | 销售 |
| GMV | 有效支付订单paid_amount之和，不直接扣退款 | 销售规模 |
| 净销售 | 同口径支付金额−成功退款金额 | 真实收入方向，退款归属期需冻结 |
| 客单价 | GMV/支付订单数 | 订单价值 |
| refund_rate v2 | 有成功退款的支付订单数/支付订单数 | 退款风险；不是退款事件条数比 |
| full_refund_rate | 全额退款支付订单数/支付订单数 | 全额退款风险 |
| buy_rate/cart_rate | 支付/加购去重用户数÷浏览去重用户数 | 标注独立集合或严格cohort |
| repeat_rate | 有效购买≥2次用户/支付用户；完全退款不算有效复购订单 | 声明观察期和变体 |
| product_heat | 1·ln(1+PV)+2·ln(1+收藏)+3·ln(1+加购)+5·ln(1+支付件数) | 版本化业务权重，不称学习模型 |
| RFM | R距最后有效购买天数；F观察期有效订单数；M观察期金额 | M精确退款口径见G-05 |

黄金55条历史标准值：PV7、UV3、DAU3、支付订单5、GMV2042.00、净销售1493.00、客单价408.40、退款率0.6000、全退款率0.2000、购买转化1.0000。只针对该输入和对应定义版本，不可套到30条旧黄金或其他批次。

### 11.3 漏斗

首版当前存在日粒度宽松漏斗view/intent/order/pay，各步独立去重。后一步可能大于前一步（例如用户此前浏览，本期支付），该情况不是自动造假或质量失败；保留真实数值，标注“非严格同cohort”。禁止min截断。历史提案“各步必须单调”不能用于宽松模式验收。

严格顺序漏斗是明确另外一种定义：以同source+user+session或时间窗口为cohort，排序后找按顺序到达步骤，才可检验单调。分类/渠道粒度见G-04；未决不输出假的分类下钻。总用户不等于各分类distinct之和，不能以此对账。

### 11.4 RFM、留存和复购

R低更好，F/M高更好；五分位评分，按高/低组合得到8类。NTILE的同值加稳定源/用户ID排序保证可复现，但同值用户可能被拆分，必须展示评分规则；是否改为同值同分属于口径变化。记录R/F/M原值、score、segment、窗口、rule_version，不仅存标签。小样本明确“仅演示”。

留存用注册或首次行为cohort，D+N活跃人数/基期cohort人数；观察窗口尚未覆盖D+N时为数据不足，不判0。复购区分支付复购/有效复购，取消不计、全退是否剔除按当前有效口径。M不明时保留null+警告，不能把缺列当0。

KMeans增强实验可对R/F/M做log1p及标准化，固定seed、k候选和训练窗口，使用轮廓系数比较；不是首版分层算法必要依赖。

### 11.5 商品、分类、地区和库存

商品排行按热度/销量/金额并有稳定次序键。分类/地区金额求和必须包含unknown，不丢未匹配维度；分类数不必等于全部商品目录分类数（无销售分类可为0/不出现，页面规则明确）。地区、商品等distinct买家不能相加当总买家。

ABC可按累计金额比例分层（阈值作为版本配置，不嵌业务常量多处）；用于库存/商品优先级建议，不声称预测。库存覆盖=可用库存/近N天平均净售出件数；分母0返回不可计算；周转需要平均库存成本，无cost时不可计算。缺库存流就显示“缺少库存数据”，不可从订单数虚构库存。

### 11.6 异常与贡献

至少14个可比历史点；默认可采用滚动均值z-score（|z|≥2.5为候选）或经版本选择的中位数/MAD，不能同一规则无记录随机切算法。标准差/MAD为0用批准绝对阈值；缺窗口不生成有置信度的统计异常。IQR留作后续对照，不把旧7点方案同时视为当前默认。

异常结构：metricCode、sourceId、window、actual、baseline、deviation、threshold、algorithmVersion、snapshotId、evidenceRefs、limitations。维度贡献为当前−基准，同口径总变化为0时不算占比；正负变化抵消可使贡献占比超过100%，不强行截断。只说明关联和核查方向，不做未经实验的因果结论。

### 12.4 质量门目标与当前F-88边界

目标流程：先冻结规则集→计算actual并判断threshold→得到有效severity→汇总门禁。ERROR/BLOCKING失败阻断，WARN/INFO持久化可见但不阻断。未知ruleCode不能照来路WARN放行；应拒绝发布并标未登记。

原始重复事件只有确定性去重已证且重复率不超过批准阈值时可观察。EVENT_ID_UNIQUE历史dupRateMax=0.0005不能为了黄金测试通过而改大。超阈值升阻断，测试fixture需正/负分开；如果业务要改变阈值先正式裁决。

**当前实现差异**：DataQualityGate.decisionForRun(runId)仍采用QualityRuleCatalog.DEFAULT.freeze(null)，显式重载可接调用方冻结集；它不按结果行rule_fingerprint恢复历史规则。写侧四列已接入，不等于读侧历史版本复算已完成。该剩余工作归F-93及相关backlog；F-88仍限定验收，不阻塞无关业务开发。

**目标约束**：历史兼容限定source/rule/version或明确批次范围，并带compatPolicyVersion。不改变历史原severity，不无条件读时重算为最新等级；历史缺版本记录UNKNOWN/需解释，不能默认为WARN/PASS。历史staging存在不等于当前混快照，后者必须阻断。

### 12.5 发布顺序与恢复

```text
Spark ADS暂存 -> 数据质量通过 -> Hive不可变发布制品
-> mxp导出+manifest/checksum -> MySQL BUILDING/staging
-> 表形/行数/金额/定义版本/内容验证
-> 单数据库事务：旧ACTIVE归档，新快照ACTIVE
-> API/页面/AI固定读取新snapshotId
```

Hive和MySQL没有宣称分布式原子事务。MySQL ACTIVE是在线发布权威；Hive已经准备好但导入失败时维持旧MySQL指针，记录待重试/对账制品。MySQL不能先切ACTIVE再导入，避免空快照暴露。

现有analytics_metric.metric_snapshot的uk_active_profile(runtime_profile_id,active_flag)保证每profile最多一个active_flag=1；非ACTIVE为NULL允许历史多行。首次没有快照合法，不能把“无ACTIVE”一概当损坏；成功链必须能建立一个。G-03未决前，此键不自动证明source隔离；读取归档需真实源归属，不能按当前profile推断历史源。

目标故障验收：导出不完整、checksum错、DB中断、质量阻断、发布并发分别触发后，新ACTIVE不存在，旧ACTIVE值/hash保持，失败run可定位。归档显式读取按权限审计；指定不存在snapshot不偷偷回最新。

### 12.6 MetricStore

当前存在MySqlMetricStore；其现有接口为type()/query(MetricQuery)/publish(SnapshotRef,List<MetricValue>)/healthCheck()，MetricQuery只有snapshotId/latestActive，扩展源/维度筛选时须核对专题服务而非假定接口已支持。以下为扩展目标：Hive降级仅管理员显式，固定source/date/definition/snapshot，使用只读账号；DorisMetricStore第二阶段；ClickHouse接口声明NOT_IMPLEMENTED。HDFS不能直接替代MySQL JDBC接口，需要Hive/Spark查询或发布适配。

Store能力描述包括supportsSnapshot、supportsDimensions、maxRows、queryTimeout、availability，不仅一个枚举。管理员切换先健康/权限/同值预检，新Store缺数据不能静默展示空0。AI与固定页面从同一语义目录、快照和权限范围读取。

## 13. AI智能分析和受控建仓

### 13.1 横向能力而非孤立聊天页

**阶段6硬边界**：AI分析只消费稳定ADS/已发布指标快照及由这些数据构建的EvidencePackage；不扫描原始DWD，不直读Landing/ODS或商城业务库。指标问数、异常解释、报告草稿和决策建议在此边界内完成。来源理解、字段映射和建仓蓝图属于后续独立AIW方向，不在阶段6开放原始数据访问。确定性系统负责画像统计、指标数值、权限和执行。LLM不能自己算金额后替换MetricStore结果，不能把预测猜想写成事实。

LlmProvider输入为用例、已脱敏上下文、结构化Schema、promptVersion和预算；返回结果显式携带providerUsed/model/token/耗时/错误。当前通过“文本是否变化”推断providerUsed的历史方式不可靠，需改为真实调用链记录。Mock、template、llm三种证据分开，模型超时后模板成功不记真实模型成功。

### 13.2 EvidencePackage

最小结构：evidenceId、templateVersion、sourceId、snapshotId、definitionVersion、generatedAt、period、comparisonPeriod、facts、comparisons、dimensions、anomalies、dataQuality、lineage、warnings。

每条事实有metricCode、value、unit、evidenceRef；比较由程序计算delta/deltaRate；不存在基期为null+NO_COMPARISON_PERIOD。缺分类/地区表为空数组+UNKNOWN_DIMENSION_TABLE，不让LLM猜比例。证据历史复现需要保存可回读的快照与模板版本及证据hash；现有只存evidenceId不能自动证明历史可重建，补可验证持久化/引用设计，不在不同存储中维护两份可变事实。

固定六段模板：发生什么、上期比较、维度贡献、质量可信度、核查/行动、限制。LLM只改写解释。输出数值守卫对照证据引用，发现新编数字拒绝该输出并回模板。AI反馈记录有用/无用/原因、用户与证据版本，用于质量评测，不让用户评价直接改变指标公式。

### 13.3 Text-to-SQL实际首版边界

当前R8更严格的规则优先，不能恢复旧设计“3表/CTE/1000行”的宽松上限：

- 语义目录仅包含已发布MySQL ADS及真实列，当前5张登记，不代表8张全部可问；扩充前验schema和权限。
- 单SELECT、单表；禁止JOIN、UNION、子查询、CTE、DDL/DML、SELECT *；递归校验列与函数白名单。
- 强制授权source作用域、允许snapshot和日期范围；MySQL ADS日期字符串为yyyyMMdd，不能输出ISO字面量静默0行。
- 扫描最多90天，LIMIT上限200，查询超时30秒；成本默认预估50万行阈值，EXPLAIN失败/空计划/不可解析也拒绝。
- 已有函数名单SUM/AVG/COUNT/MIN/MAX/ROUND/ABS/COALESCE/IFNULL/FLOOR/CEIL/DATE/CAST，增加函数需验证。
- 问句筛与SQL AST是两道独立防线；危险问句不能被回退层偷偷变成正常SELECT后记“攻击测试通过”。
- 只读DataSource+数据库SELECT权限+setReadOnly+timeout/maxRows同时生效，审计拒绝动作。
- 最多一次受控修复，修复后重新走全校验；不能反复修到绕过规则。

用户问的是不支持关联的复杂问题时应明确能力限制，可由固定专题API回答；不为提高AI通过率放开安全限制。

### 13.4 模型治理

凭据只通过credentialRef/受保护配置注入，文档不写真密钥。限制请求字节、输出token、单次/每日预算、并发、重试和熔断。requestFingerprint包含source/snapshot/问题/模型/promptVersion；provider不支持幂等时，超时可能已计费，记录不确定性，不承诺traceId可防所有重复扣费。

样本列名、注释和内容都是不可信数据；先PII脱敏后再发模型，提示中明确其不是指令。不能给模型SSH、数据库写账号或任意本地目录。真实模型试验需正样本、拒绝样本、超时和非法JSON，不是只检查Provider类存在。

### 14.2 状态和权限

DRAFT→PENDING_REVIEW→APPROVED→IN_PROGRESS→COMPLETED→EVALUATING→EFFECTIVE/PARTIAL/INEFFECTIVE/INSUFFICIENT_DATA。拒审REJECTED，取消CANCELLED，需理由。当前保留PENDING_REVIEW，不另改PENDING_APPROVAL制造旧数据迁移。

登录主体决定创建人、审批人、执行人，不接受请求体伪造身份。提交时核完整行动/负责人/目标/窗口/证据；不齐拒绝。非法流转也留审计，不能只有成功日志。审批不等于已经执行商业动作。

### 14.3 效果算法

目标为等长、完整、同来源、同口径的前后窗口聚合，不是只取两个端点快照。加和型指标按相同周期汇总或周期均值；比例型指标先汇总分子分母再相除，不能平均每天的比率。baseline=0时相对改善不可计算，显示绝对差并按批准目标规则评价。

改善方向=(actual−baseline)/abs(baseline)，越低越好取反；达到目标EFFECTIVE、达到部分阈值PARTIAL、无改善INEFFECTIVE；缺日/缺样本/缺口径/数据异常为INSUFFICIENT_DATA。阈值随模板版本，不凭模型自由下结论。至少构造四类可达样本，使用不同真实窗口并独立重算oracle。前后对比只说明变化，不声称行动造成变化。

### 14.4 业务报告

经营日报/周报、订单专题、商品异常、用户运营、决策效果六类模板是产品报告，不等同毕业论文。数字/图表由程序生成；AI只写摘要、建议和限制。reportInstance保存source/snapshot/definition/template/prompt版本、创建者、状态、artifact引用与checksum。未实现的模板标待实现，不用一张摘要页宣称六类齐全。

## 17. 安全、权限与异常边界

### 17.1 身份与数据权限

现有角色admin/data_dev/analyst/operator；RolePermissions当前给operator的部分技术权限不等于目标已细化。收紧角色时先列兼容矩阵，不以隐藏菜单代替后端鉴权。创建人、审批人取登录主体，不信任X-User-Id或请求体身份。商城和平台token独立。

所有来源、快照、决策及AI请求按对象作用域授权。AI继承用户权限，不持有商城写账户、元库管理员、SSH或任意文件访问权。允许查询的ADS列由语义目录与真实schema交集决定，不自动把新表开放给AI。目标发布/查询分账号，读取侧只SELECT；AI异常失败关闭。

### 17.2 当前测试隔离实现

- 实例隔离与身份校验是两层：只允许3307测试目标；canonical身份为实际`@@hostname:@@port`，trim并仅对hostname忽略大小写后比较。裸hostname、裸port、localhost别名兜底、uuid替代身份均不得通过。
- `@@server_uuid`单独读取、缺失拒绝、用于漂移事实，不替代hostname:port。MySQL主版本用SELECT VERSION()解析，不用不存在的@@version_major。
- 只读检查目标库、授权范围、角色/账号及实例事实；不能把GRANT USAGE误判写授权，也不能忽略反引号库名。
- 使用runId隔离库/账户/临时根，默认档不触发外部DB；真库IT先门禁后DDL。
- generator的IsolatedSchemaInitializer在GeneratorMetaStoreTest前执行门禁→Flyway→表存在性检查，已解决新runId首跑5E，不再写“需同库二跑才绿”。
- metric-analysis的isolated-tests profile按it标签收集IsolationGuardMySqlIT；依赖模块platform-common不重复计入隔离55。
- D-5应用启动前全DataSource门禁尚有缺口，不以IT门禁通过声称所有应用启动已安全。3306保持写冻结；隔离启动须逐项检查实际连接，不能盲用默认application配置。
- 日常应用和IT不用root。隔离bootstrap管理身份与受限运行身份分离；已有工具的显式授权要求不得省略。

### 17.3 凭据、路径、留存

凭据使用受保护环境注入或经实现支持的credentialRef，不把字符串credref本身当密码。runner接收环境变量，不提供-Password；不把真实口令写文档、命令示例、日志或证据。不同模块解析能力按实现校核，不能声明一个抽象就已统一全部凭据。

输入URI/路径解析后限制在授权根，禁止..、符号链接/UNC/任意URL逃逸。Spark参数用白名单及参数列表，SSH场景另做转义校验，不拼接不可信shell。日志对token/password/Authorization脱敏。WSL不默认开放公网。

旧保留期只是规划候选，未授权自动删除。ACTIVE、决策引用、在途run、待恢复输入不得清理。3307历史对象清理在backlog，须专门白名单和授权；历史checkpoint、worktree及acceptance不在本轮清理范围。

| 类别 | 处理目标 |
|---|---|
| 契约/映射/坏数据 | 隔离原文与reason，不推进错误输入为成功 |
| 配置/权限/schema | 执行前失败并显示管理员可做动作，不自动改权限/建正式库 |
| Spark失败/网络超时 | 记录externalJobId、日志、attempt；核外部状态后有限重试 |
| 质量失败 | 定位rule/stage/version，阻断发布、保留旧ACTIVE |
| 发布导入失败 | 保留制品与旧快照，验证后幂等重试，不伪装跨系统原子事务 |
| 未知快照/无数据 | 明确不存在或不足，不静默回最新/填0 |
| AI超时/非法输出/拒绝 | 标明template或REJECTED，不假称真实模型成功 |
| 页面过时响应 | 切源/时间后取消旧请求或丢弃旧响应，避免混源 |

### 18.2 使用与退出语义

```powershell
# 默认档；路径与JDK实际安装不同时通过参数覆盖
pwsh -NoProfile -File scripts/run-tests.ps1 -Suite default
# Spark算法档，显式使用入口配置的JDK8
pwsh -NoProfile -File scripts/run-tests.ps1 -Suite spark
# 隔离实例、受限账号和新RunId已准备后使用；口令由受保护环境注入
pwsh -NoProfile -File scripts/run-tests.ps1 -Suite isolated -RunId dev3_20260915_case01 -Confirm
pwsh -NoProfile -File scripts/run-tests.ps1 -Suite all -RunId dev3_20260915_case02 -Confirm
```

这些是后续使用说明，本轮不执行。isolated/all并不自动授权创建或清理库；预先按已批准流程准备相同runId对应数据库和账号。Maven负责各POM内includes/groups/excludedGroups；PowerShell负责跨模块/JDK/环境，不新增根POM、不以点名一个类代替标准收集。

runner当前可覆盖MavenCmd、MavenRepoLocal、JdkDefault、JdkSpark、IsolatedScript、LogDir。当前默认含Windows安装路径，移到Linux不能直接冒充已兼容；Linux入口是否新增由总控安排，不阻塞Windows调用WSL依赖。RunId形状为首位字母数字，其余字母数字/下划线/连字符，总长6–64。

退出码：0全部所选档通过；1参数/环境错误；5执行前拒绝；6隔离探针失败；7套件失败、0用例、非零F/E、报告不新鲜或计数漂移。all任一档失败或0 tests整体失败。AllowCountDrift只有总控批准基线变化后使用，新增合法用例不能靠删测试维持旧数字，也不能自行放宽门禁。
