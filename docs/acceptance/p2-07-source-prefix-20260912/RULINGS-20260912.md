## 一、裁决

### D-070 唯一所有者：数仓前缀的事实来源迁到源级，取值链只留一条
`source_registry` 成为数仓库名前缀的**唯一事实来源**。`WarehouseNamespaceProvider` 增加 `WarehouseNamespace forSource(Long sourceId)`；`current()` **改为经 ACTIVE 档案的 `source_id` 解析**（即 `current()` = `forSource(ACTIVE profile.source_id)`），不再直接读 `runtime_profile.hive_database_prefix`。取值链唯一化后：`source_registry.warehouse_prefix → WarehouseNamespace`。所有拼库名的消费方（`JobCommandBuilder`、`EvidenceBuilder`、P4 页面）只经该接口，**不得各自读列**。

### D-071 列语义（Q2＋Q6）：`warehouse_prefix VARCHAR(24) NOT NULL`，不设 DEFAULT
- 列名 `warehouse_prefix`（**不沿用** `hive_database_prefix`：沿用会掩盖「所有者已搬迁」）。
- 宽度 **24** = 契约正则 `^[a-z][a-z0-9_]{0,23}$` 的上限 ⇒ 库里存得下的形状必然合法，消灭「库里能存、代码拒收」的窗口。
- **不设 `DEFAULT 'dw'`**：默认值会让"忘记填"静默落进源 A 的库 —— 正是要防的场景。
- NULL 语义 = **不允许**（方案丙）。V18 三步 = `ADD COLUMN … NULL` → `UPDATE … SET 'dw', updated_at = updated_at WHERE warehouse_prefix IS NULL` → `MODIFY COLUMN … NOT NULL`。回填写 `updated_at = updated_at` 使其**不伪装成人工编辑**（V16 先例）；`MODIFY … NOT NULL` **本身即断言**：漏回填任何一行，迁移直接失败（V17 先例）。
- 零迁移等价性（问 6）：唯一源 `mock-mall` 的 profile 前缀为 NULL ⇒ 今日解析为 `dw`；源级回填同为 `'dw'` ⇒ 五个库名 `dw_ods/dw_dwd/dw_dim/dw_dws/dw_ads` **字节级不变**。

### D-072 契约（Q1）：属**破坏性变更** ⇒ 出 v2 文件 ＋ `VERSION` major 递增
`contract-specs/specs/warehouse-namespace.v1.json:30` 的 `sourceOfTruth` 把 `runtime_profile.hive_database_prefix` 写成事实来源；改它属**改语义**，按 `contract-specs/README.md:42`「不原地改语义」⇒ **新增 `contract-specs/specs/warehouse-namespace.v2.json`**（带 `supersedes: warehouse-namespace.v1.json`、`status: FROZEN-2026-09-12`、`sourceOfTruth` 指向 `source_registry.warehouse_prefix`），`contract-specs/VERSION` 由 `1.3.0` → **`2.0.0`**，并在 `contract-specs/README.md` 的规格清单里把权威版本标为 v2（v1 保留为历史冻结件）。**v1 文件本身不得改动**（历史冻结件，append-only）。
