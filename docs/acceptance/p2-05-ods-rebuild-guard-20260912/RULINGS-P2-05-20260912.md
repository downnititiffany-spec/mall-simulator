## 1. 正式裁定（号段 D-127 … D-134）

### D-127 —— 「旧 ACTIVE 可读」的验收口径（语义边界）

- **裁定**：按指导书字面判据验收，**验收口径限定在元数据与指标值层**：重建失败后，旧 `metric_snapshot` 行（现为 `S20260901_43` / `id=26` / `active_flag=1`）**仍可查、其指标值不变**。
- **物理层「可重算」明确列为未满足/未实测**：ODS 无 `snapshot_id` 隔离 ⇒ 分区被覆盖后旧快照**无法重算**。此条必须写入交付报告的限制清单。
- **禁止**声称：「回退可用」「还原已验证」「重建可逆」。**不得**为凑判据给 ODS 加 `snapshot_id` 分区（属结构性大改，越出本行范围，须单独裁决）。

### D-128 —— 备份清单粒度 = 受影响表 × 受影响分区

- **裁定**：只备份**本次重建会触及**的分区（`dt`/`hour` 维度），不做整库/整层快照。
- 清单字段（最小集）：`库.表.分区`、文件数、行数、总字节、**逐文件 sha256**、生成时刻、触发 `pipeline_run_id`。
- 理由：①ODS 表分区是覆盖单位，备份粒度与之对齐才能做到「失败可定位」；②整库快照与陷阱 #26（本机资源上限）冲突。

### D-129 —— 清单载体＝文件清单；**不分配迁移号**

- **裁定**：清单与副本落**文件**（建议 `warehouse/_rebuild_backup/<runId>/manifest.json` ＋ 分区副本），**不新建 MySQL 表** ⇒ **不分配 V19**（迁移号只由总控分配，本裁决明确「不分配」）。
- 审计复用既有 `operation_audit_log`（92 行，动作码族 `DECISION_*`/`USER_*`/`AI_QUERY`），依 **D-035「不建第二张审计表」**。
- **不得**自行编号迁移文件（`V19__…` 一律禁止出现在交付面）。

### D-130 —— 失败语义：保旧 ACTIVE 元数据不变 ＋ **不自动还原**

- **裁定**：守卫失败 ⇒ ①旧 `metric_snapshot` 状态**不变**；②**不自动还原**分区文件；③**停下并报告**（含清单路径与差异）；④还原是**显式操作**，执行前须**用户按范围确认**（Data Destruction Guard）。
- 理由：自动还原会掩盖失败、破坏可观测性，并可能在半还原状态下制造第二份不一致数据。
- **不得**把「有备份」写成「已可回滚」。

### D-131 —— **不准改** `PipelineService` / `SparkStageExecutor`

- **裁定**：本行守卫**整体落在 `spark-jobs` 侧**；**不改**管线编排热点文件（C 类小项禁占）。
- 挂载点：复用**既有** `INIT_SCHEMA` 阶段（实测 `PipelineService.java:206 / 407-412`，`SparkStageExecutor.java:44` → `sci`，且位于 `LOAD_ODS` 之前）⇒ 无需新增阶段、无需改动编排层。
- **不得**新增阶段码或改动阶段顺序。

### D-132 —— 审计动作码与资源类型**冻结**

- **裁定**（一经冻结不得改名）：
  - 动作码：`WAREHOUSE_REBUILD_BACKUP`、`WAREHOUSE_REBUILD_GUARD_BLOCK`、`WAREHOUSE_REBUILD_RESTORE`
  - 资源类型：`WAREHOUSE_PARTITION`
- 写入既有 `operation_audit_log`；**不得**新增审计表、不得复用 `DECISION_*` 语义。
