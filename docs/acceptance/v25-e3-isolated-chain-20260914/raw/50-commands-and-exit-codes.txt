### A) 先确定「退出码」怎么读（实测，不是推测）
背景：链路 1 的作业报告 exit code 1，而脚本 20 的失败分支是 exit 4 —— 差异必须先解释清楚才能引用退出码。
探针脚本 D:\Develop_code\GraduationProject\target\e3-run\_exittest\exit4.ps1 内容： Write-Host "reached end"; exit 4

A-1 前台直接调用（无管道）:
    PS> & pwsh -NoProfile -File "D:\Develop_code\GraduationProject\target\e3-run\_exittest\exit4.ps1"; $LASTEXITCODE
    reached end
    LASTEXITCODE=4
A-2 前台 + 与作业相同的管道包装 (*>&1 | Tee-Object -FilePath ...):
    LASTEXITCODE=4     （管道不会吞掉内部脚本的 exit 4）
A-3 同一条命令**作为后台作业**运行:
    作业输出: reached end
    作业最终状态: [status: completed, exit code: 1]

结论（可复现）：本会话的**后台作业层把任何非零退出码归一化为 1**，因此：
  · 作业 pwsh-44（链路 2）exit 0  ⇔ 脚本走到 xit 0（SUCCESS 分支）
  · 作业 pwsh-43（链路 1）exit 1  ⇔ 脚本走到 xit 4（runStatus -ne SUCCESS 分支）——**不是**异常/崩溃
  · 作业 pwsh-37（启动 8091）exit 0  ⇔ java 进程结束、启动脚本正常返回
  反之，凡我在前台直接执行的脚本，退出码为真实值（见 B 表 where=前台）。
  未取证：链路 1 那次作业是否可能因别的原因非零 —— 判据是 raw/20-chain-console.log 末行完整打印了
  "[E3 汇总] ... 终态=FAILED"，即脚本执行到最后一行才退出。

### C) 脚本 30 第 1 次的假不一致（自曝缺陷，保留证据不删）
