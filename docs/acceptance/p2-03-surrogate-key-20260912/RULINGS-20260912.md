## 一、独立复核结论（先给证据，再给裁决）

总控未采信泳道自报的向量表，用 Python **独立重实现**规则并逐条对账（脚本 `.verify/p2-03-vector-recheck.py`，结果 `.verify/p2-03-vectors-verified.json`）：

| 项 | 实测 |
|---|---|
| 向量条数 | 22 条（10 列，无表头） |
| 摘要一致（`sha256` 列） | 22/22 一致 ⇒ 材料构成 `source\|entity\|NORMALIZED` 与每行的 raw/normalized 记法**已复现** |
| `key_hex8` 列一致 | **12/22**；**10 条不一致**（V04/V06/V07/V08/V11/V17/V18/V19/V20/V22） |
| 不一致的性质 | 这 10 条摘要首字节 **≥ 0x80**：泳道列写的是**摘要前 8 字节原值**（如 `d30271ac8944a9b3`），按其在方案描述里声明的「**清符号位**」规则应为 `530271ac8944a9b3`。二者作为有符号 BIGINT 分属**负数/非负**两个域 |
| 空值记号 | V13/V14/V15 三行用 `(空)`/`(null)` 散文记号表示「不生成键」；按字面值计算会**凭空生成一个键**（总控首轮复核即踩中 V15：得到 `mock-mall\|user\|(NULL)` 的键） |
| 关键不变量（按裁决口径复算后） | 不同 `(source,entity,normalized)` 三元组 **17 个 → 17 个不同键**（无碰撞）；同一三元组必同键（`U000065` 组＝`530271ac8944a9b3`；UUID 大写组＝`21f71a4b7c67bfae`）；20 个键**全部非负且 ≠ 0** |

**判据缺陷 A（载体语义歧义）**：`key_hex8` 一列同时被当作「摘要前缀」与「最终键值」两种含义使用，没有机器可读的区分 ⇒ 任何独立实现都会与它分歧。
**判据缺陷 B（散文记号）**：用人类语言记号表示空值，使「不生成键」这一**行为要求**无法被自动核对，且会误导独立实现生成伪键。
两缺陷**不改泳道文件**（`raw/draft-vectors.tsv` 原样保留为历史取证），处置 = 规格内**同时**给出 `digestPrefixHex16` 与 `keyHex16`/`keyBigint` 两列 + 用 `expect: "KEY" | "NULL_KEY"` 机器可读字段取代散文记号。
登记为一类**新陷阱**（第五例）：**列名/记号缺少机器可读语义 ⇒ 独立复核必然分歧**；前四例为 `-match` 命中自述文本、驱动断言落在不会输出该字段的通道、守卫键命中裁决行自身的引文、幂等键用文件名而非目录限定相对路径。

## 二、D-083 … D-092 裁决

### D-083 材料构成取 **A2**＝源 + 实体 + 归一化实体 id（并保留原值）
`material = <sourceCode>|<entity>|<normalizedRawId>`。**拒绝 A1**（只规范化 id）：跨源同名 id 会合并，直接违背「多商城各自分析」的既定目标。**拒绝 A3**（把层名/列名并入材料）：身份一旦依赖存储位置，同一实体在 ODS 与 DWD 会得到不同键，join 语义崩坏。
实体枚举：`user` / `product` / `category` / `brand` / `coupon`。
**DIM/DWD 同时保留 `raw_*_id` 原值与代理键**（Q9）：代理键作 join 主键，原值作可追溯证据（分析系统必须能解释自己的数字）。
**事件粒度键 `event_id`/`behavior_id` 不在本规格范围**（见 D-090）。

### D-084 归一化＝去首尾空白 + **文化无关大写**；其余一律不归一
`trim` 后 `toUpperCase(Locale.ROOT)`（Java `Locale.ROOT`／Scala `Locale.ROOT`；禁止依赖默认区域，避免土耳其语 `i/İ` 类问题）；编码固定 **UTF-8**。
**不做**：NFKC/NFKD 等 Unicode 归一、内部空白压缩、字母剥离（`U000065` 保持 `U000065`，**不得**剥成 `650`）、全角/半角转换。
理由：`sourceCode` 已在材料内 ⇒ 大小写归一**不可能**造成跨源合并；异构源对同一实体可能给不同大小写，归一提高一致性。同时拒绝过度归一：`U 65` 与 `U65` 视为**不同实体**。
（与 warehouse-namespace 的 `noNormalization` 不冲突：那条约束管的是**配置值**必须原样失败，本条管的是**数据值**的键派生。）

### D-085 键值表示取 **B1** 的加强版：前 8 字节 → **清符号位** → 全零取 1
`SHA-256(material)` 取前 8 字节，`b[0] &= 0x7F`，结果为 0 时取 1 ⇒ 键恒在 `[1, 2^63-1]`，类型 `BIGINT`。
理由：清符号位使键**恒非负**，不与 `-1`（unknown 哨兵，见 DWD 的 `COALESCE(...,-1)`）语义混淆；全零摘要（概率 ~2^-63）取 1 以免出现 `0` 键。
**拒绝 B2**（完整 256 位）：需 STRING/DECIMAL 承载，Hive join 成本与现有 BIGINT 维表冲突。**拒绝 B3**（自增）：不可复现 ⇒ 重跑不可幂等，违反本项目流水线的基本要求。

### D-086 材料单射性写成硬约束（这是 A2+D-084 能成立的**前提**）
前提两条：① `sourceCode` 与 `entity` **不含分隔符 `|`**；② `rawId` **位于末位**且归一化后原样拼接。满足前提时材料对 `(source,entity,rawId)` 单射 ⇒ 内含 `|` 的 id 也不会碰撞（**新增向量 V23** 已独立复算：`A\|B` 得 `02ad50110670929c`，与 V01–V22 任一键不同）。
**未来新增任何组件（层名、租户、时间片等）之前，必须先改为长度前缀编码**（`len:value` 逐段），否则单射性不再成立。

### D-087 空/缺失 id：**不生成键**（NULL）+ 记 DQ + **不丢行**
`rawId` 为 NULL / 空串 / 全空白 ⇒ 键列为 `NULL`，记入数据质量明细，**不进 quarantine、不丢行**（行数守恒优先于完整性）。
**禁止**静默映射到 `0`/`-1`/任何哨兵键（否则所有无 id 行会合并成一条）；**禁止**把多个空 id 行合并。
规格用 `expect: "KEY" | "NULL_KEY"` 表达，不再用散文记号（判据缺陷 B 的处置）。

### D-088 草案向量的处置：以总控独立复算为准，泳道读数原样留存
`contract-specs/specs/surrogate-key.v1.json` 内的 23 条向量为**总控独立复算值**（Python 实现 D-083…D-087 口径），并同时含 `digestPrefixHex16` 与 `keyHex16`/`keyBigint`，从载体上消除判据缺陷 A。
泳道 `raw/draft-vectors.tsv` 与 `draft-vectors-console.txt` **一字不改**（历史取证）；其与规格的 10 条 `key_hex8` 差异按「未施加清符号位」解释，属**载体口径差异**，不据此判定泳道"算错"。
规格状态 = **`DRAFT-2026-09-12`**：冻结门槛仍按 `contract-specs/README.md` §3（结构对账测试转绿 + 总控审阅），**现在不满足**。

### D-089 源画像 `surrogate` 字段收敛（Q11）
源画像的代理键声明**必须**是本契约的算法名（现行唯一允许值 `HASH64`，其语义**由本规格定义**），源画像**不得**自定义算法或参数；声明非法一律**拒绝**（fail-closed，不做静默兜底）。P1-03 侧该字段此前只有"声明"没有"生产者"，与之**收敛**而非并存：实现落地后，声明值与契约算法名不一致的源画像不得 ACTIVE。

### D-090 生成器不改；`IdCodec` 旧口径按 anti-entropy 退役，但**本轮不排删除动作**
- 生成器跨源复用 `U%06d`（Q12）：**无需改**。源已入材料 ⇒ `U00000001@A` 与 `U00000001@B` 必得不同键，命名空间问题在键派生侧解决。
- `IdCodec.scala` 的「剥字母转 BIGINT」摧毁前缀命名空间（`U00000001` 与 `O00000001` **都归一为 1**）：判为陈旧重复所有者。
  - **Deletion Class**：`code-retirement`（内部代码退役，非持久状态、非对外契约）。
  - **Retirement Decision**：路径 `delete-first`，但**新所有者尚未承载行为**（本规格无实现、无复跑）⇒ 按 anti-entropy 的 `missing-owner-logic` 处理：**先补新所有者**。次序 = ①加法新增代理键列 → ②按本规格实现派生 → ③55 条黄金链（T2）复跑通过 → ④**方可在后续轮**删除旧口径与其依赖测试。
  - 本轮**不执行**任何删除、**不发出**可运行的删除命令；`IdCodec` 现状仍在主路径上承载行为，**不得**声称"已替换/已退役"。
- `event_id`/`behavior_id`（Q14）：**不触碰**，唯一所有者仍为 `DwdSql.scala:31`（D-055）。
