## 4. 结论与残留

- **代码侧闭环**：键的规范形式收敛到唯一所有者 `LocalFileIngestor.checkpointKey/canonical`（读写共用），
  状态计数口径收敛到"当前环境目录内已建立断点的文件数"，并有 E2（5 个断言先红后绿）+ E3（读数端/不重读/正路径）证据。
- **历史数据未合并（有意为之）**：`file_checkpoint` 里 50 行 `\.\` 历史写法仍在，属**不可逆数据变更**，
  按反熵纪律需用户按范围确认后才可删/合并（卡片见《开发过程事实与决策记录》DEF-13「数据销毁守卫」）。
  在未合并状态下，读数、唯一键匹配、增量推进均已正确（§3.1–§3.3 实测）。
- **口径变更提示**：15:50 / 15:55 两份验收记录里的 `checkpointFiles`（100 / 101）是**旧口径**（全表行数）的原始观测，
  按"证据不可改写"原则保留原文，不作为当前口径引用。
- **landing 目录副作用**：本次夹具文件成为常驻数据（52 个文件 / 404,139,515 字节），
  后续采集门禁的 `pendingFiles/pendingBytes` 基线随之为 52 / 404,139,515。
