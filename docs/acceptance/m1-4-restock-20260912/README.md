## 6. 顺带发现 F-16：`scripts/start-all.ps1` 末行会让调用方永不返回

**现场**：两次调用都在目标程序已健康之后卡死——① `-MallOnly`（管道接 `Tee-Object`）挂满 420 s 被杀；② `-GeneratorOnly`（改用 `*>` 文件重定向，**无管道**）仍挂满 240 s 被杀。第 ② 次是关键对照：**文件重定向不产生匿名管道**，却同样挂住 ⇒ 我最初的"子进程继承管道写端导致 EOF 不来"的假设被这次实测**否定**。

**定位**：`scripts/start-all.ps1:96` 是脚本最后一条语句

```powershell
try { Start-Process ("http://127.0.0.1:" + $openPort) } catch {}
```

两次现场都停在它之前——日志与标准输出都已打到最后一行（商城 `商城入口：http://127.0.0.1:8090/`、生成器 `生成器 OK → …`），而这两行正是 L93/L89，紧邻 L96。**症状与"打开默认浏览器的 `Start-Process` 不返回"一致**（`try/catch` 只吞异常，不设超时）。

**影响与处置建议**：脚本本身能起服务（java 是 `Start-Process -WindowStyle Hidden` 独立进程，父进程被杀不影响它），但**任何把 `start-all.ps1` 当子步骤调用的自动化（含 `run-demo.ps1` 类脚本、CI、总控取证）都会永久挂住**。建议后续给它加 `-NoBrowser` 开关（或把 L96 换成 `Start-Process -FilePath $url` 之外的实现并设超时），属**脚本健壮性**问题，不影响 M1-8 的启停结论。本轮不改源码，只登记。
