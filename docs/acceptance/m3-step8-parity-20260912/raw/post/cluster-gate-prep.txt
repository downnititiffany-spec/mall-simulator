### 7A.1 读侧必须**钉 `snapshot_id`**，**禁止**依赖 `active_flag=1`（缺陷 **F-98**）
**实测事实**：同快照重导时，profile 1 的 ACTIVE 指针**空缺约 170 ms**

**⇒ 纪律（强制）**：
- §5.5 的**每一次**对账查询**必须**写成「**指定 `snapshot_id`** ＋ **指定 `runtime_profile_id`**」的形式。

- 查询**原文**与**执行时刻**必须一并留档。

**标准查询模板（留档用，逐字复制）**：
```sql
-- 快照元信息（钉 snapshot_id）
SELECT id, snapshot_id, pipeline_run_id, status, version, active_flag, published_at

SELECT m.metric_code, m.metric_value, m.period

```

### 7.2 【强制前置检查 (a)】磁盘清单面：现在会被选中的批次是谁
**命令原文**（只读，读 `landing/manifests/*.json`，复刻 `findReadyManifest` 判据）：
```powershell
Get-ChildItem -LiteralPath 'landing\manifests' -Filter '*.json' | ForEach-Object {
  $j = Get-Content -LiteralPath $_.FullName -Raw | ConvertFrom-Json
  $acc=[int]$j.acceptedRecords; $q=[int]$j.quarantinedRecords
  if ($j.status -eq 'READY' -and ($acc+$q) -gt 0) {
    [pscustomobject]@{ File=$_.Name; BatchId=[int]$j.batchId; Acc=$acc; Q=$q;
                       Source=$j.sourceCode; FileList=($j.files.file -join ','); AcceptedUri=$j.acceptedUri }
  }
} | Sort-Object BatchId | Format-Table -AutoSize
```
**实测输出（本轮原文要点）**：磁盘上满足判据的清单共 **33** 个（batchId 2…43）；
**MAX ACCEPTED batchId = 43**（`43.json`）：
```
>>> MAX ACCEPTED batchId on disk = 43  (file 43.json)
>>> sourceCode=mock-mall  accepted=51 quarantined=4
>>> files[].file = m3s8-golden55-20260912210313.jsonl
>>> acceptedUri = accepted/43
```
**业务日归属核验**：`landing/accepted/43/` 仅含 `m3s8-golden55-20260912210313.jsonl`，
首条 `event_time = 09/01/2026 09:00:00` ⇒ **属 2026-09-01 切片**，**不是夹具批次**。
（⚠️ 注意：`ConvertFrom-Json` 会把 ISO 时间**本地化成 `MM/dd/yyyy`**；判定业务日时以原始 JSONL 文本为准。）
**通过条件**：max accepted batchId 的 `sourceCode`／`files[].file`／accepted／quarantined
必须 = **`mock-mall` / `m3s8-golden55-20260912210313.jsonl` / 51 / 4**，且业务日 = **2026-09-01**。

### 7.3 【强制前置检查 (b)】钉住面：有没有未终态 run 钉住一个已不在磁盘上的批次
**命令原文**（只读，锚定 + 有界提取 `"batchId":N`，**规避陷阱 #59**）：
