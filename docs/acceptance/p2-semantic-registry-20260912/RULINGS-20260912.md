## D-095（TQ-1，最高优先级）—— 映射载体 = **③ 两者并存，但所有权严格不重叠**

- **裁定**：**采纳 ③**：
  1. **文件（源画像）拥有**「源词汇 → canonical」这一段：每个源一份版本化 JSON，随 git 变更 ⇒ 保住设计 `:149` 的**接入证据**（"接入新商城 = 新增一个 JSON"）。
  2. **DB 拥有**「canonical → 分析含义」的注册表 + **生效状态/版本/生效区间**（可查询、可审核）⇒ 满足 V2.4 L344–L350「版本化配置**和审核记录**」与 L324 `schema_mapping`、L348「没有 ACTIVE mapping ⇒ 隔离」所需的**可查询 ACTIVE 状态**。
  3. **不得双向**：DB 中**不得**出现"源词汇→canonical"的第二份权威副本；文件里**不得**定义 canonical 字段集（见 D-099）。任何一侧出现对方职责的副本 ⇒ 视为**重复所有者**，按反熵纪律**先立新所有者、再删旧副本**，且删除需总控确认。
- **理由**：设计 `:213` 已给出边界原则（"profile 管源词汇→canonical；DB 管 canonical→分析含义"）；模式 B（配置驱动映射）与之同向；③ 唯一代价"双所有者风险"由上述不重叠切分与"禁双向"条款消解。
- **代价（明示）**：契约工作量最大（源画像契约 + 语义注册表契约两份），且必须同批落锚点与版本号（见 D-102/D-101）。

## D-097（TQ-7 ＋ F-41 合并）—— `source_system` 必须改为**由源提供**，纳入契约变更批

- **裁定**：`canonical-event.v1.schema.json` 把 `source_system` 钉成 `const: "mock-mall"`（契约 `:39`）与既有 **F-41**（`EventContract.java:17` 字面量 `"mock-mall"` ＋ `CanonicalEventSchemaParityTest:65-73` 把 schema `const` 锁死）**是同一处冲突**：与「分析系统不得与商城写死」「数据类型/种类不得写死」的既定方针**直接冲突**，且**接第二个源（P5 异种源 B）时必然撞上**。

## D-098（TQ-12）—— 真实画像**求实**，另立**测试夹具画像**取得映射能力证据

- **裁定**：**采纳"分流"**（不是 TQ-12 的两个原选项之一）：
  1. `mock-mall.v1.json`（P3-01 交付物）**照实**写参考商城的**同名映射**。**禁止**把它写成"故意错位"的词汇表来制造证据 —— 那是**把 Mock 当真实**，违反铁律。
  2. 为了取得"映射真的生效"的证据，**另立一份测试夹具画像**（非真实源；文件名与目录须能一眼区分，如 `fixtures/vocab-shifted.v1.json`，并在文件内 `x-contract-status` 标注"测试夹具、非真实源"），用它做 E2/E3 的映射能力证明。
  3. 正式的异源映射证据**待 P5 异种源 B 接入后**取得。
- **理由**：直击看板已登记的 **F-25**（参考商城状态词与规范 enum 恰好同名，**掩盖**了"缺少映射"，第二适配器会立刻暴露）⇒ 若只有同名画像，"没有映射"与"映射正确"在证据上不可分。

## D-099（TQ-11）—— canonical 骨架的**唯一所有者**是契约 schema

- **裁定**：`contract-specs/schemas/canonical-event.v1.schema.json` 的 properties/`$defs` 是 canonical 字段集的**唯一所有者**；源画像与语义注册表**只做映射**，**不得**重新定义 canonical 字段集、**不得**新增 canonical 字段。
- **冲突口径**：两个源映射到同一 canonical 字段时**不冲突**（多对一是映射的常态）；真正需要唯一性的是 **canonical 骨架**，已由本条钉住。
- **设计 `:147` 的落实**：「缺失的映射项 = 该源没有这个语义（不是默认值）」⇒ 实现侧**禁止**任何"缺映射就给默认值"的兜底路径。

## D-100（TQ-13）—— 映射层**不新增物理落层**；namespace 解析**单一所有者**

- **裁定**：
  1. 映射层**不新增**物理落库层：canonical 事件的物理形态就是 **landing 的规范事件 JSON**（既有物），ODS 侧由 P2-01 的 `payload_json` **原样保真**承载。
  2. 映射层的产物 = **源画像（文件）＋ 语义注册表（DB）**，供分析侧**按源解释** canonical 字段。
  3. **namespace 解析的单一所有者 = 既有 `ActiveProfileWarehouseNamespaceProvider`**（由快照 `sourceId` 解析一次，P2-07 已在其上工作）；映射层**不得**自建第二条解析链，`raw_path`/"源级 ODS"/命名空间三处**共用同一 `sourceId` 链**。
- **理由**：RECON 已警示三处会互相踩；单一所有者是防踩的唯一低成本办法。
