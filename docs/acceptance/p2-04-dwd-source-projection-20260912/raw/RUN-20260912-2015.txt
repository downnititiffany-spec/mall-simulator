===== R-11 IdCodec 通用 CAST BIGINT 现状（P2-04 要求禁止通用 CAST） =====
blob=6aad5bd8013d3a315b1c150ba70bd1e4733e7efc lines=49
   1: package com.graduation.analytics.sql
   2: 
   3: /**
   4:  * 契约字符串 id → 数仓 BIGINT 代理键的**唯一**映射规则。
   5:  *
   6:  * 背景（DEF-05，实测）：冻结契约把身份放在 `payload` 内的**字符串**字段
   7:  * （`user_id=U000065`、`product_id=P00030`、`order_id=O00000001`、`category_id=C0001`、`brand_id=B0001`），
   8:  * 而数仓 `dwd/dws/ads/dim` 的 id 列是 `BIGINT`；直接 `CAST(... AS BIGINT)` 会**静默返回 NULL**
   9:  * （run 36 实测：ODS `U000058` → NULL，DWD `rows=13 / null_uid=13 / null_pid=13`），
  10:  * 导致 `PUB_DQ_BLOCKING_RULES`(13/13) 与 `ADS_STAGING_KEY_NOT_NULL`(3/14) 阻断发布。
  11:  *
  12:  * 决策：B-07 候选 ② / D-023——**只在 ODS→DWD 边界做一次归一化**，数仓模型、指标、页面与已发布快照都不动。
  13:  * 规则 = **全匹配**「字母前缀 + 纯数字」才转 `BIGINT`，否则 `NULL`（由质量规则判定，**不静默兜底成 0**）。
  14:  * 全匹配（而不是"剥前缀后尽力解析"）是有意的：`U12A`/`U-1`/`view` 这类取值必须得到 `NULL`，
  15:  * 否则 `U-1` 会被解析成 `-1`，与维度表的 unknown key 哨兵 `-1` 混淆（`IdCodecSpec` 已固化该断言）。
  16:  *
  17:  * 纪律：该规则**只在此处定义**。任何地方都不得再手写 `CAST(payload_*_id AS BIGINT)`
  18:  * （`IdCodecSpec` 会扫描三个 SQL 模板对象做负向守卫）。
  19:  */
  20: object IdCodec {
  21: 
  22:   /**
  23:    * 契约 id 的完整形状：可选字母前缀 + 纯数字。
  24:    * group 1 = 数字部分（user `U000065` → `000065`；product `P00030` → `00030`；纯数字 `123` → `123`）。

  37:   def toBIGINT(expr: String): String =
  38:     s"CAST(REGEXP_EXTRACT($expr, '$IdPattern', 1) AS BIGINT)"
  39: 
  40:   /**

  43:    */
  44:   def normalize(id: String): Option[Long] =
  45:     Option(id)
  46:       .filter(_.matches(IdShape))
  47:       .map(_.replaceAll("^[A-Za-z]+", ""))
  48:       .flatMap(s => scala.util.Try(s.toLong).toOption)
  49: }
