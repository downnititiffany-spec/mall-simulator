## 1. 正式裁定（号段 D-121 … D-126）

### D-121 —— P2-04 拆行：「去重键复合化」可做，「SourceProfile 投影」不在本行

- **裁定**：本行拆为两半，状态与依赖分别登记。
  - **P2-04-a 去重键复合化**：**可实施**。理由：去重键口径**已由冻结契约（权威 ①）改为复合键**（§0 实测），实现仍是单一 `event_id` ⇒ 这是**实现与冻结契约不一致**的缺陷，不是新需求。落点＝DWD 去重窗口（`DwdSql.scala`，HEAD 版本在 L31 的 `PARTITION BY event_id`）＋ 使得 ODS/DWD 侧确实存在可用的源身份列（见 D-122）。
  - **P2-04-b 从 SourceProfile 投影生成 DWD 字段**：**不在本行实施**。理由：真实 `SourceProfile` 属 **P3-01** 交付面、归一属 **P3-02**，本行依赖列写作「P2-02/03」不含 P3 ⇒ 前提不成立。**不得**用自造 profile 冒充（「Mock 不当真实」）。
- **登记要求**：看板行 223 追加补记（原文不改）：依赖改为「P2-03 收工后可做 **P2-04-a**；**P2-04-b** 依赖 P3-01、P3-02」；状态在 P2-04-a 未取证前**不得**升为 `DONE`。
- **出口判据（P2-04-a）**：本地链（E3）上，同一 `event_id` 分属两个源实例时**不再互相去重**；单源下该性质**必然退化为与旧行为等价** ⇒ 证据必须来自构造夹具（D-126）。

### D-122 —— 源身份的**物理承载列 = `source_system`**，不新增列

- **裁定**：契约逻辑名 `source_instance_id` 的物理承载＝**既有列 `source_system`**（注入值，per-source 下发，与 namespace 前缀同源）。
  - 理由：①该列已在数据面存在且被 D-056 明确为「本轮注入值」；②`source_registry` 为**每源一行**、库名前缀按源下发 ⇒ 「源实例」在本项目就是「源」这一粒度；③新增 `source_instance_id` 列要在 DDL、ODS v2 列集、契约别名、ADS/快照四处扩散，而冻结决策 ④（每源独立 namespace）已把源身份编码进**库空间**。
- **必须同做的说明**：在实现侧（及契约侧的下一次修订）写一行**别名映射说明**：契约 `source_instance_id` ⇔ 物理 `source_system`。**只加说明，不改语义、不改列名**。
- **不得**：把 `raw_source_system`（行内原值，D-056）当作去重键输入 —— 去重键用**注入值** `source_system`，`raw_source_system` 只保留行内差异以供审计。

### D-123 —— 源身份**不向指标快照做列级传播**（本轮）

- **裁定**：V2.4 L314 / L426 提到的「传播到指标快照」**本轮不实施**，另立待办并标注**未实现**。
- 理由：①`metric_snapshot` 实测**无**该列，其 `source` 列实测值为发布方 `spark-ads`，**不是**源身份 ⇒ 不得把 `source` 当源身份使用；②源身份已由 **per-source warehouse namespace**（冻结决策 ④）承载，跨源不会互相覆盖；③列级传播属加法，可在 P3 阶段与真实多源一起验收，单独提前做只会产生无法证伪的字段。
- **不得声称**「源身份已全程传播」或「指标快照可按源过滤」。

### D-124 —— 与 P2-03 的顺序与所有者边界

- **裁定**：
  1. **顺序**：`P2-03 落地并收工` → 才开工 `P2-04-a`（同一文件、同一行区间，禁并发）。
  2. **所有者边界不变**：`event_id` / `behavior_id` 的唯一所有者仍是 `DwdSql.scala` 的去重定义（D-055、P2-03 的 D-090 Q14）⇒ P2-04-a **只扩键**（把源身份加入去重分区/键），**不得**改 `event_id` 的生成、归一或编码规则。
  3. 施工前**必须**按 D-091 Q17 重新取行号与 blob 哈希（worktree 已被 P2-03 改动，行号已漂移到 L46 一带），不得沿用草案行号。

### D-125 —— `IdCodec` 的「缺失 vs 脏数据」本轮不动

- **裁定**：**不修改** `IdCodec`（P2-03 期间它是受保护对象），**不新增列**。
- 「缺字段显式 NULL + DQ」用**既有原因码**表达（如 `MISSING_REQUIRED_FIELD` 等既有 21 类），需要区分 missing / dirty 时**新增 DQ 规则**而不是改归一函数。
- **不得**以「为了区分」为由改动 P2-03 已冻结的归一契约。

### D-126 —— D-054 追认、P2-06 重测时点、以及两条「不可证伪」的取证口径

1. **D-054「4 列 vs 5 列」**：已于 2026-09-12 20:18 由总控追认 **「以 5 列为准」**（`docs/acceptance/p2-01-ods-v2-spec-draft-20260912/RULINGS.md` 追认节，父侧只读复算：`raw_source_system` 0→3 命中，正对照 `source_system` 11）⇒ 本条**无需再裁**，P2-04 直接按 5 列前提工作。
2. **P2-06 重测时点**：P2-04-a 落地后，在**本地链（E3）**重测；测试输入必须是**构造的双源夹具**。
3. **不可证伪项的取证纪律（本轮新增口径）**：
   - 跨源去重正确性 **只认构造夹具 + 本地链**；**E4 集群不得作为跨源证据**（真库单源，D-126 前提）。
   - 单源真库上**禁止**写「跨源去重正确」；最多写「单源下新旧键行为等价（退化为等价）」。
   - 因此 P2-04-a 的状态上限为 **`DONE_LIMITED`**，除非将来出现第二个源实例。
