# V3.0 答辩演示手册

本手册为现行答辩演示依据，完整覆盖基于当前前端 Web 系统的两条交互演示路径（普通员工路径与管理员路径）。系统演示运行于本地单节点 LOCAL 模式，采用「三程序、三端口、三套库」架构：分析平台（`platform-app`，`:8091`，分析与日常操作入口）、模拟商城（`reference-mall`，`:8090`，演示商城与商品后台）、合成数据生成器（`synthetic-data-generator`，`:8092`，独立造数服务）。前端可通过开发服务（`http://127.0.0.1:5173`，代理至 8091）或平台内置页面（`http://127.0.0.1:8091/`）访问。

---

## §0 边界先行

1. **限定通过口径**：如实说明本系统为增量完善后的演示版本。系统原签收结论为「限定通过」（main 分支 `d9cdd6b`），本手册的编写属于开发线（`codex/cloud-v3-development`）上的增量文档健全工作，不升级原签收定性，未测范围与诚实边界详见文末 §7。
2. **AI 解释来源口径**：在未配置真实商业大模型 API Key 或外部网络不可达时，系统的智能问答与建议功能自动降级至确定性规则模板引擎，页面上如实明确标注「解释最终来源：template」，并给出规则回退限制说明，严禁假冒真实大模型输出；真实大模型实测冒烟为答辩机本地独立事项（RES-01），由总控按 STAGE6 清单单独审核，不在本手册内预先宣称已验。
3. **数据口径**：所有业务分析指标与看板数据均来自当前生效的 `ACTIVE` 快照（以本地环境实际存在的已激活快照编号为准，不预设任何具体快照编号）；前端页面仅忠实呈现后端发布的数据与元数据，前端不做任何二次聚合或推算。

## §1 准备与启动

### 1.1 服务启动

打开 PowerShell 终端，在仓库根目录下执行一键启动命令：

```powershell
pwsh -File scripts/start-all.ps1
```

> **提示**：若仅演示分析平台功能，可按需添加参数仅启动分析平台进程：
> ```powershell
> pwsh -File scripts/start-all.ps1 -PlatformOnly
> ```
> 其余单程序启动参数包括：`-MallOnly`（仅启动模拟商城）、`-GeneratorOnly`（仅启动生成器）。

### 1.2 演示账号与口令口径

本系统预置三类角色账号供演示使用，口令取自本地种子数据或本地环境配置，**本手册严禁列出任何真实口令字符串**：

| 角色定位 | 用户名 | 登录口令 | 适用演示路径 |
|---|---|---|---|
| **系统管理员** | `admin` | `<本地种子口令>` | §3 管理员路径（治理、向导、环境、流水线、运维） |
| **运营专员** | `operator` | `<本地种子口令>` | §2 普通员工路径（大盘、看板、决策、报告） |
| **数据分析师** | `analyst` | `<本地种子口令>` | §2 普通员工路径（大盘、看板、AI 问数、报告） |

### 1.3 启动完成判据

启动完成后，通过以下不带凭据的健康检查端点及端口监听状态确认服务就绪：

1. **HTTP 探活检查**：
   - 分析平台：浏览器或终端访问 `http://127.0.0.1:8091/api/v1/metrics/health`，返回 HTTP 200 且状态为 `UP` 即就绪；
   - 模拟商城：访问 `http://127.0.0.1:8090/`，SPA 首页正常返回即就绪；
   - 合成数据生成器：访问 `http://127.0.0.1:8092/api/v1/scenarios`，接口返回场景列表即就绪。
2. **端口监听确认（PowerShell）**：
   ```powershell
   Get-NetTCPConnection -LocalPort 8091, 8090, 8092 -State Listen
   ```
   看到对应端口处于 `Listen` 状态即表示后端程序启动完成。

### 1.4 前端打开方式

- **方式一（推荐，开发模式）**：在 `web/` 目录下执行 `npm run dev`，启动本地前端开发服务，使用现代浏览器（Chromium / Firefox）打开 `http://127.0.0.1:5173/`（该服务已自动将 `/api` 请求代理转发至后端的 `8091` 端口）。
- **方式二（生产静态托管模式）**：若已执行完整构建打包，直接通过浏览器访问分析平台内置端口：`http://127.0.0.1:8091/`。

## §2 普通员工路径（9 步）

适用演示角色：数据分析师（`analyst`）或运营专员（`operator`）。

### 步骤 1：登录与安全回跳

- **操作**：
  1. 在浏览器未登录状态下，直接在地址栏输入一个受保护的页面 URL，例如访问 `http://127.0.0.1:5173/reports`；
  2. 观察页面自动拦截跳转至登录页 `/login`；
  3. 在登录表单输入分析师用户名 `analyst` 与 `<本地种子口令>`，点击「登 录」按钮。
- **预期现象**：
  1. 访问受保护页面被路由守卫自动拦截，URL 携带重定向参数（如 `/login?redirect=%2Freports`）；
  2. 登录按钮在提交时呈现防重点击的加载态；
  3. 登录成功后，系统根据 `redirect` 参数自动安全回跳至原目标页面 `/reports`（若访问根路径则默认进入 `/overview` 运营大盘）；
  4. 页面顶栏右侧清晰展示当前登录人姓名与「数据分析师」角色徽标。
- **异常时**：
  若提示「用户名或密码错误」，请核验本地种子配置；若登录后未跳转，可就地再次点击「登 录」；若接口报错无响应，使用 §1.3 检查 8091 端口健康检查。

### 步骤 2：快照与业务上下文核查

- **操作**：
  1. 进入运营大盘页面（`/overview`）；
  2. 观察页面顶部公共工具栏的 `SnapshotSelector` 快照下拉框与按 ID 查看输入框；
  3. 查看页面主体顶部的 `AnalysisContext` 业务上下文元数据条。
- **预期现象**：
  1. `SnapshotSelector` 下拉框默认自动选中当前生效的 `ACTIVE` 快照（显示本地实际存在的快照编号与口径版本，不写死固定快照编号）；
  2. 下方提示文字明确标明「本页数据固定使用 <当前ACTIVE快照号>（<口径版本>）」；
  3. `AnalysisContext` 上下文条完整回显 8 项关键元数据（其中生效查询范围在有查询窗口时显示）：快照编号、生效查询范围、业务来源 ID、业务时间、数据更新时间、来源（发布方，并标注「非业务源身份」提示）、口径版本以及质量状态（显示绿色 `PASS` 徽标）。
- **异常时**：
  若快照下拉框提示「暂无可选快照」，点击提示后的「重试」按钮；若误输入了不存在的快照 ID 导致锁定，点击表单中的「返回当前档案快照」按钮就地复位。

### 步骤 3：运营大盘日期筛选 Enter 提交

- **操作**：
  1. 在运营大盘顶部筛选栏，点击修改「趋势日期范围」的起始日期或结束日期输入框；
  2. 在日期输入框获得焦点状态下，直接按下键盘 `Enter` 键。
- **预期现象**：
  1. 敲击 `Enter` 键就地触发数据加载（无需手动使用鼠标寻找点击「加载」按钮，符合 U06-S12 纯键盘体验）；
  2. 顶部 GMV、净销售额、客单价、支付订单数、UV、DAU 6 个指标卡稳定展示当期快照数值，下方销售趋势图与活跃趋势图平滑重新渲染；
  3. 筛选栏右侧清晰提示「日期范围只作用于趋势，指标卡固定取本次快照」，口径透明；若加载中途发生错误，页面保留上一次成功的图表数据，并在上方展示错误横幅（符合 U03-S01 错误态旧数据保留）。
- **异常时**：
  若输入的起始日期晚于结束日期，筛选栏下方展示红色日期范围校验错误；若趋势图加载失败，点击图表遮罩内的「重试」按钮就地重试。

### 步骤 4：分析看板浏览（漏斗/商品/分层/销售）

- **操作**：
  依次点击侧边栏菜单，浏览各专业分析视图：
  1. 点击「用户行为分析」（`/behavior`）：查看转化漏斗图（300px）与 3 列漏斗阶段明细表（阶段/用户数/转化率，转化率取后端快照口径，前端不重算）；
  2. 点击「商品分析」（`/products`）：查看商品热度排行图、商品转化图与 8 列商品明细表；拖动表格下方的水平滚动条；使用键盘 Tab 键聚焦表头的 `.sort-btn` 排序按钮，敲击 Enter 键测试排序切换；
  3. 点击「用户分层」（`/rfm`）：查看 RFM 八类分群散点矩阵（300px）与 4 列分层明细表；核查表中若存在缺失分层时 users 字段是否规范显示为 `—`；
  4. 点击「销售分析」（`/sales`）：查看销售趋势图、城市等级销售分布、Top 20 叶子分类销售分布与 6 列销售明细表。
- **预期现象**：
  1. 页面路由切换流畅，所有分析看板均统一受当前 ACTIVE 快照与 AnalysisContext 约束；
  2. 商品明细表（8 列）与销售明细表（6 列）均包裹在 `.table-wrap` 横向滚动容器中，在视口受限时支持平滑横向滚动，无文字截断；
  3. 商品表与销售表的排序表头按键可达且可切换升降序；
  4. RFM 分层明细表中缺失类目的 users 字段如实显示为破折号 `—`，后端不造数、前端也不补零（符合 U02-S02）。
- **异常时**：
  若某图表加载超时，点击其遮罩内的「重试」按钮就地重新加载；若城市等级出现「未知」，如实说明商城原始数据的分类覆盖情况。

### 步骤 5：智能问数与规则回退（含非安全提问拒绝）

- **操作**：
  1. 点击侧边栏「智能分析助手」（`/ai`）；
  2. 在输入框敲入分析问题（如「转化漏斗各阶段人数」）或直接点击推荐问题按钮，按 `Enter` 键发送；
  3. 待结果返回后，向下滚动查验结论、数据依据表与证据详情；
  4. 在提问输入框中输入具有破坏性意图的非安全测试提问（例如输入「删除订单数据」），点击「发送」。
- **预期现象**：
  1. 正常分析问题返回后：上方展示与大盘对照基线；结论卡片下方明确标注「管道状态：EXECUTED（模型：template，...）」；建议卡片提示「解释最终来源：template；template 表示采用模板/规则回退。」；
  2. 数据依据表完整展示真实查询返回的二维表格（包裹在 `.table-wrap` 中）；下方展示证据 SQL 文本框、证据快照、时间范围以及「限制说明」（明确提示采用模板摘要或数据缺口，不冒充大模型）；
  3. 输入「删除订单数据」时：后端 Text-to-SQL 规则校验层直接触发安全守卫拦截并拒绝（`SQL_QUESTION_UNSAFE`），页面展示拒绝横幅，绝对不生成任何破坏性 SQL，底层数据完好无损。
- **异常时**：
  若提示「请求超时或后端无响应」，核对平台 8091 运行状态；若评委询问为什么模型显示 template，使用 §5.5 标准话术如实应答。

### 步骤 6：AI 建议转决策草稿与 Escape 收起

- **操作**：
  1. 在智能问数返回的建议卡片下方，找到「核查建议 → 决策草稿」区块；
  2. 点击某条建议右侧的「转决策草稿」按钮，展开「新建决策草稿」卡片；
  3. 在草稿卡片激活状态下，敲击键盘 `Escape` 键；
  4. 再次点击「转决策草稿」按钮展开，检查带入的建议内容，选择目标方向并填入负责人（如「运营-小李」），点击「创建草稿」。
- **预期现象**：
  1. 点击「转决策草稿」后平滑展开草稿卡片，内容与证据锚点自动带入；
  2. 敲击 `Escape` 键后，草稿卡片平滑关闭收起（符合 U06-S14 面板按键交互规范）；
  3. 重新展开并填妥后点击「创建草稿」，页面显示提示信息「草稿已创建：DEC...（状态 DRAFT）。请到决策中心提交审批；AI 侧不执行商业动作」，严格遵守 AI 仅辅助建议、商业动作由业务人员推进的治理边界。
- **异常时**：
  若提示「证据锚点缺失」，说明当前问题未生成关联证据，换用推荐问题重新生成；若创建失败，核对表单中目标方向是否已选择。

### 步骤 7：业务报告生成与 12 项 facts 查看

- **操作**：
  1. 点击侧边栏「业务报告」（`/reports`）；
  2. 在「生成业务报告」表单中，选择模板「OPS_DAILY」（日常经营报告），选择当前 `ACTIVE` 快照（业务日自动联动带出），点击「生成日常经营报告」按钮；
  3. 在下方的「我的报告」列表中找到刚才生成的报告行，点击操作列的「查看证据」按钮；
  4. 展开报告证据详情后，核验各项结构化字段，并点击右上角「读取完整制品」；
  5. 按浏览器刷新快捷键（F5 或 Ctrl+R）刷新整个页面。
- **预期现象**：
  1. 点击生成后按钮呈现防重点击状态，生成成功后列表自动更新出现新报告；
  2. 点击「查看证据」后展示规范的 12 项 facts 事实数据（包含数据快照、报告窗口、质量门、已发布指标、对比指标、警告数、报告摘要项、指标证据表等），指标表格包裹在 `.report-table-scroll` 中可横向滚动；
  3. 点击「读取完整制品」后，完整展开原始 JSON 制品，可直接审阅底层快照与计算元数据；
  4. 页面刷新后，已生成的报告列表依旧完整保留在表格中，不闪空、不丢失（符合 U05-S01 报告刷新保留）。
- **异常时**：
  若生成失败提示「暂无可用的已发布快照」，检查当前环境是否存在 ACTIVE 快照；若刷新后详情收起，在列表中重新点击「查看证据」即可恢复查看。

### 步骤 8：决策审批页面内对话框与评价 INSUFFICIENT_DATA 诚实呈现

- **操作**：
  1. 点击侧边栏「决策中心」（`/decisions`）；
  2. 在 13 列决策列表中找到步骤 6 生成的处于 `DRAFT` 状态的决策行，点击操作列的「提交审核」按钮，在弹出的输入区确认负责人并提交；
  3. 决策状态更新为 `PENDING_REVIEW` 后，点击「批准」按钮；
  4. 观察弹出的**页面内对话框**（U05-S03），敲击 `Escape` 键测试取消；再次点击「批准」，在对话框中分别录入负责人与截止日期（格式为 `YYYY-MM-DD`），点击「确定」；
  5. 状态流转为 `APPROVED` 后，依次点击「开始」（状态变为 `IN_PROGRESS`）与「完成」（状态变为 `COMPLETED`）；
  6. 状态变为 `COMPLETED` 后，点击操作列的「评价」按钮，查验效果列呈现的评价结论。
- **预期现象**：
  1. 彻底淘汰了浏览器原生 `prompt()` 连续弹窗，全部审批交互均在页面内对话框（`chart-box` 内嵌卡片）中完成，单对话框一次性采集负责人与截止日期两个字段；
  2. 对话框支持按 `Escape` 取消或按回车确定；
  3. 决策状态严格按照 `DRAFT → PENDING_REVIEW → APPROVED → IN_PROGRESS → COMPLETED` 顺序流转；
  4. 触发评价后，效果列诚实呈现 `INSUFFICIENT_DATA`（数据不足），并展示基线快照与实际快照对比信息，如实说明当前指标缺少多日窗口公式、不盲目伪造改善率，体现严谨的数据科学态度。
- **异常时**：
  若录入截止日期格式错误，对话框提示「截止日期格式必须为 YYYY-MM-DD」；若操作中途网络抖动，点击右上角「刷新」按钮重试。

### 步骤 9：安全注销

- **操作**：
  在系统任意页面，点击前端顶栏右侧的「退出登录」按钮。
- **预期现象**：
  系统立即调用退出接口清除本地缓存的令牌与用户信息，平滑重定向回登录页 `/login`；在浏览器中点击「后退」按钮被路由守卫直接拦截并保持在登录页，会话完全闭环。
- **异常时**：
  若点击退出未重定向，手动刷新浏览器或直接在地址栏输入 `/login`。

## §3 管理员路径（5 步）

适用演示角色：系统管理员（`admin`）。

### 步骤 1：管理员登录与系统治理导航

- **操作**：
  在登录页（`/login`）输入管理员用户名 `admin` 与 `<本地种子口令>`，点击「登 录」。
- **预期现象**：
  1. 成功进入系统，顶栏身份徽标明确显示为「系统管理员」；
  2. 左侧侧边栏除常规分析与决策分组外，展开专属的「系统治理」导航分组，包含四个管理模块：接入向导、运行环境、数据流水线、运维中心。
- **异常时**：
  若侧边栏未展现「系统治理」分组，核实登录账号是否为 `admin`；若为普通用户登录态残留，先点击注销后重新登录。

### 步骤 2：来源接入向导四步

## §4 停服口径

演示完毕后，必须严格按照**先停前端、再停后端**的顺序安全停服。

### 4.1 前端停止

若前端是通过终端 `npm run dev` 启动的开发服务，直接在运行前端的终端窗口中按下 `Ctrl + C` 正常终止服务。

### 4.2 后端停服原则与规范

在停服后端 Java 进程时，必须严格遵守以下安全纪律：
- **严禁按端口杀进程**（按端口盲杀可能误杀操作系统上其他绑定相似端口的无关关键进程）；
- **严禁假定旧 PID 仍有效**（进程重新启动后 PID 发生漂移，使用硬编码或过期的 PID 极易误伤系统其他应用）；
- **必须按进程命令行全匹配定位终止**：通过进程命令行中的特征参数精确识别本系统 3 个 Java 进程后逐个优雅终止。

### 4.3 规范停服脚本示例（PowerShell）

打开 PowerShell，执行以下基于 `Win32_Process` 命令行过滤的停服脚本：

```powershell
# 查找并终止属于本系统的三个 Java 进程（命令行包含对应 jar 特征）
Get-CimInstance Win32_Process -Filter "Name = 'java.exe'" | Where-Object {
    $_.CommandLine -match 'platform-app' -or
    $_.CommandLine -match 'mall-simulator' -or
    $_.CommandLine -match 'synthetic-data-generator'
} | ForEach-Object {
    Write-Host "正在终止本系统进程 PID: $($_.ProcessId) -> $($_.CommandLine)"
    Stop-Process -Id $_.ProcessId -PassThru
}
```

### 4.4 停服完成确认

执行以下端口监听检查命令，确认三个后端端口均已释放且不再监听：

```powershell
Get-NetTCPConnection -LocalPort 8090, 8091, 8092 -State Listen -ErrorAction SilentlyContinue
```

> **判据**：若上述命令无任何输出，即表明三个服务端口均已完全关闭，停服安全完成。

## §5 应急恢复入口汇总

演示过程中若遇突发异常，可直接使用系统内已存在的机制就地恢复，无需慌乱（本节仅列出系统已存在的真实机制，严禁凭空编造不存在的功能）：

1. **图表局部错误态就地重试**：
   - 场景：网络瞬时抖动导致某个看板图表请求失败。
   - 恢复：直接点击错误图表遮罩层正中央的「重试」按钮（ChartState 组件提供，U03-S02），就地重新拉取该图表数据，无需刷新全页面，当前筛选条件完整保留。
2. **切回当前 ACTIVE 快照**：
   - 场景：在快照选择器中误输入了历史快照或未发布的无效快照导致数据为空。
   - 恢复：点击顶部工具栏中的「返回当前档案快照」按钮，系统自动复位并重新加载当前有效的 `ACTIVE` 快照数据。
3. **服务未就绪时重启单个程序**：
   - 场景：演示中途某个单体进程（如商城或生成器）异常退出。
   - 恢复：无需全量重启所有服务，使用启动脚本的单程序参数单独拉起对应进程：
     - 单独拉起平台：`pwsh -File scripts/start-all.ps1 -PlatformOnly`
     - 单独拉起商城：`pwsh -File scripts/start-all.ps1 -MallOnly`
     - 单独拉起生成器：`pwsh -File scripts/start-all.ps1 -GeneratorOnly`
4. **流水线阶段中断恢复**：
   - 场景：数据流水线在某一计算阶段意外失败。
   - 恢复：进入数据流水线页面，在失败实例旁点击「续跑」，在表单中选择失败的起始阶段 `fromStage` 并录入原因，系统将自动从失败断点继续计算，已成功前缀不重复计算。
5. **AI 规则回退与透明性话术**：
   - 场景：评委提问「为什么模型显示 template 而不是大模型？」
   - 标准应答话术：「本系统采用受控 AI 架构，核心结论由语义解析生成 Text-to-SQL 查询确定性宽表。当未配置商业大模型出口时，系统自动安全降级至确定性规则模板引擎，页面如实显示 `template` 来源并给出完整限制说明，数据依据与 SQL 全程透明可溯源，绝不伪造虚假模型结论。」
