## 问题与修复

`runOnce()` 和 `retry()` 原先把提交调用与随后列表刷新放在同一个 `try/catch` 中。后端已返回 RunId 后，如果列表刷新抛错，异常分支会把 `runResult` 改写成 `FAILED: ...`，尽管任务已创建且进度轮询已启动。

新增 `refreshRunsAfterSubmission()` 作为列表刷新的错误边界。列表失败仍由 `useAnalysis` 管理和呈现，不会更改提交/重试接口返回的运行结果。创建与重试流程均复用该处理。
