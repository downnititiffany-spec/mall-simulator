## 执行顺序与验收判据

1. 保护基线：确认 HEAD、11 项既有改动及冻结文件状态；所有改动只增补，不覆盖。
2. 环境 smoke：只复用已验证安装；专用 MySQL 仅 127.0.0.1:3307；启动/健康检查步骤脚本化；凭据只在进程内存中；检查 HDFS namespace 身份，绝不格式化。
3. 服务与浏览器：共享 Thrift HMS 与两种嵌入 Derby 分开；显式 Linux 配置启动分析平台、商城、生成器和两前端；健康、登录、前端实际请求各自后端均须成功。
4. 定向数据链：小规模、确定性数据贯通生成/商城→Flume→HDFS→摄取→ODS/DWD/DWS/ADS→3307 隔离 ACTIVE 快照→API→页面；记录 sourceId、batchId、pipeline runId、snapshotId。独立 oracle 必须在发布前从原始输入计算，逐值核对。
5. 发布语义：同源第二批确实增加期望值；无新输入不产生新 ACTIVE；注入可控失败后旧 ACTIVE 与 ADS 仍可读且未变。Spark 重任务串行。
6. 共享 HMS 单独判定：Hive Metastore Thrift 服务健康，并用独立 Spark/Hive 客户端访问该 HMS；分析平台 SINGLE_NODE 嵌入式 Derby 的结果不能替代共享 HMS 通过结论。
7. 联调收口后，从 V3.0/已确认状态选取下一项首版未完成且可执行功能，最小实现、定向测试、受影响链路验收；不得重复安装或重写已完成能力。
8. 阶段收口：需要时执行完整回归和真实单节点验证；记录测试档位分别为 smoke、单元、隔离数据库、单节点 E2E，不互相替代；更新 `PROJECT_STATUS.md`、决策/假设/回滚记录与恢复命令。
